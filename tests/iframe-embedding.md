# iframe 嵌入专项用例

使用真实浏览器检查，宿主仅由 Node 内置 HTTP 服务提供，不安装 UI/E2E 框架。

## 准备

1. 使用 `../liteCodeTool_datas/` 下独立测试目录启动应用，创建 A、B 两份大屏，分别配置可识别的标题、默认监控目标和来源。准备同目标两种来源的不同数值。
2. 开发环境运行 `npm run dev:demo`；生产环境先 `npm run build` 再 `npm run start:demo`。通过 `DATA_DIR` 和 `PORT` 等环境变量隔离数据与端口，具体命令见[开发手册](../快速开发手册.md)。
3. 启动宿主（将 ID 替换为实际创建的资源 ID）：

   ```powershell
   node tools/iframe-smoke.mjs --base http://127.0.0.1:8787 --a screen_A --b screen_B --port 8899
   ```

4. 浏览器打开 `http://127.0.0.1:8899`。宿主显示 A、B、A 对照和无效大屏四个 frame；大屏服务和宿主必须具有不同 origin。跨电脑测试时，`--base` 也须使用另一台电脑可访问的大屏服务地址。

## 操作与通过标准

| 操作 | 通过标准 |
| --- | --- |
| 打开四个 frame | A、B 显示各自真实卡片；A 对照显示 A；无效 ID 明确报错，不回退默认大屏。 |
| 推送可辨识的新数值 | 相应 frame 内的实际控件更新，连接状态正常。 |
| 仅在 A 切换监控目标和来源 | 数值对应所选来源；B 和 A 对照保持原选择；指定缺失来源不回退。 |
| 刷新 A | 恢复已保存默认值，API 回读配置不变。 |
| 双击标题、Ctrl+S、Esc | 不进入文字编辑、不保存配置、不跳回编辑器；刷新没有临时指派导致的未保存提示。 |
| 调整 frame 宽高，进入/退出全屏 | 画布适配自己的容器，控件及对象切换仍可操作。 |
| 删除大屏后刷新对应 frame | 显示资源不存在，其余 frame 继续工作。 |
| 开发与生产服务分别执行 | 深层地址刷新、跨来源加载、实时更新和来源切换均正确。 |
| 从另一台内网电脑执行 | 页面、API 与 WebSocket 可达，能加载 iframe 并接收实时更新。 |

必须进入 frame 查看内容和交互，不能将 HTTP 200、页面 load 事件或截图中的空白页面判为成功。测试宿主不会跨来源读取 frame DOM，也不自动显示“通过”。

测试结果记录服务地址、origin、所用 ID 和实际结果。日志、截图及验收报告放 `../liteCodeTool_tmp/`；无另一台电脑时，将跨机项明确标为未验证。结束后只关闭本次测试服务，不操作其他进程和用户数据。
