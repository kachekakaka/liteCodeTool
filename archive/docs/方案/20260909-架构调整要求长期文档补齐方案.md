## 3. 补齐内容

### 3.1 组件与依赖边界

在开发手册“代码放在哪里”章节集中维护以下规则，与已有内容合并，避免重复：

- 页面、公共布局、业务容器、展示组件按职责组织。App.vue 承担路由容器和全局交互，不重新承载整页业务分支、拖拽或模板编辑。
- 复杂属性区域和控件按职责拆分；不能将巨型页面或检查器整体搬到另一个文件来代替拆分。简单展示保留适当合并，不按固定行数或组件数量设门槛。
- 展示组件优先通过明确的 props 和事件协作；少量业务容器可使用对应 store，避免全量展开全局状态或大量透传整个业务对象。
- 搜索框、展开项、就地输入等局部交互状态归所属组件；跨页面保留的业务草稿归对应 store。
- 路由决定页面模式和资源身份；页面及导航协调层调用 store，store 不导入 router；底层 HTTP、实时传输和核心算法不依赖页面。
- 沿用现有 Vue 响应式状态组织；本次文档补齐不引入新的状态管理框架，也不将原任务的阶段性选择扩写为永久禁止更换框架。
- 新建或实质改写的组件采用标准 `<script setup lang="ts">`；现有组件随实际职责调整迁移，不为统一语法额外扩大改动。
- 组件专属样式随组件维护，跨组件样式明确其作用范围；调整 scoped 或加载顺序时核对既有样式，避免迁移后选择器失效。

### 3.2 初始化和实时连接

在“路由与草稿”章节补充现有初始化规则的边界：

- 应用初始化负责元数据、资产和实体底账，路由负责显式资源装载；初始化服务幂等，不依赖 App 挂载。
- 全局 WebSocket 及其重连、时钟等配套任务由应用生命周期统一管理；切换页面不反复建立连接或清空历史。
- 表格自动翻页、长按、拖拽及快捷键等局部交互的计时器和监听归所属组件或 composable，随对应生命周期创建和清理。
- 全局与局部资源各自处理销毁及热更新清理；初始化失败后重试防止重复注册连接、监听或计时器。
- 保留既有草稿保护、请求取消与旧响应隔离要求，不在此次文档整理中改变行为。

### 3.3 格式化、注释与开发保障

- 明确自有源码遵循仓库现有 Prettier 配置；保存时格式化和命令行检查使用项目本地同一套工具，具体格式参数以配置文件为准，不在文档再抄一份。
- 保留已有中文多行方法注释、参数和返回值说明、interface/type 及字段说明要求，不重复设立第二套注释规范。
- 维护现有前后端源码调试和完整离线开发要求；依赖变更后仍通过重新准备离线开发包交付。
- 将“开发必须支持的能力”与“某次已完成的验收”分开，配置存在、能启动或构建通过不能替代源码断点和实际断网验证。
- 日常修改按影响范围选择验证：文档做内容和链接检查；源码做相关格式、类型及功能验证；核心纯逻辑做针对性单测；构建、路由、调试及离线能力变更分别执行对应检查。不将完整架构改造验收作为所有修改的最低门槛，也不减免既有方案已明确的专项验收。

## 4. 实施顺序

1. 核对工作区变更、历史要求与目标章节；如文档已被其他任务更新，基于新内容合并，不覆盖他人改动。
2. 定向检查当前目录、关键模块与格式化配置，确认规则与实现一致。若发现冲突，记录具体差异，不借文档整理修改代码或静默改变已确认要求。
3. 先补齐开发手册，再更新 README、AGENTS.md 的指针和原方案的后续维护说明。
4. 按下一节完成文档验收，生成外部实施报告；本方案完成后移动到 `archive/docs/方案/`，在文件头部标明完成日期与验证结论，并修正移动后的相对链接。

## 5. 验收标准

- 历史任务中的路由、职责拆分、格式化、中文注释、前后端调试和离线开发要求均能从 AGENTS.md 或 README 进入对应长期文档；补充规则无需依赖历史聊天才能理解。
- 开发手册覆盖组件写法、状态归属、依赖方向和实时连接生命周期；既有规则合并维护，不形成重复或互相矛盾的规范。
- 构建取舍仍由 ADR 0012 维护；ADR 0007 的双轨构建已被取代这一关系保持清楚，不新增同题 ADR。
- 文档链接、章节锚点和归档后的相对路径有效；Git 差异仅包含本方案规定的文档变更。
- 不增加文件行数门槛、组件数量要求、重型测试、CI 门禁或新的审批流程。
- 本次为文档变更，只进行内容核对、链接检查和 `git diff --check`；不为此重复运行应用测试、构建、UI 或离线验收。
- 开发手册的长期验证规则明确日常按影响范围检查与专项能力验收的区别，例外不局限于本次文档任务。
- 原架构调整方案中的 VS Code 断点、完整断网及确认框取消流程待验收项保持如实记录；本次文档补齐完成不代表这些项目通过，也不触发原方案归档。
