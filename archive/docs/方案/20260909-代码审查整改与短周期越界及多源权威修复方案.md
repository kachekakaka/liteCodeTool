## 问题陈述 (Problem Statement)

在最新一轮代码审查（Code Review）中，Standards 与 Spec 两条轴线共同暴露出以下影响系统稳定性、数据真实性与工程规范的深层问题：

1. **短周期时序越界绘制（核心计算缺陷）**：
   `src/engine/core.ts` 中的滑动窗口截取纯函数 `inWindow` 强行将时间下限钳制为 1 分钟（`clamp(minutes, 1, 60)`）。当用户将图表回溯时间设置为秒级窗口（如 10s、15s、30s）时，数据池依然截取了整整 1 分钟前的数据点。导致这部分历史点在按 15s/30s 坐标系映射时计算出负向横坐标（`x < 58`），严重越界绘制到了图表左侧 Y 轴外部。
2. **多源数据权威性破坏（数据真实性隐患）**：
   纯函数 `resolveEntityRecord` 在用户指定了明确的传感器来源（如“光测1”）但该目标尚未上报该传感器数据时，平稳回退到了默认记录（如“雷达1”）。这导致大屏图例标牌显示为所选来源，曲线绘制的却是完全无关的传感器轨迹，违背了“严格槽位来源权威（Strict Slot Source Authority）”的设计原则。
3. **工坊预览目标单点覆盖与模板持久化污染**：
   在组件工坊中选择预览目标时，直接将属性写入了控件持久化契约（`control.props.workshopPreviewTarget`），导致该临时调试数据被保存进模板 JSON 中；且预览目标粗暴覆盖全部槽位，导致工坊无法预览多槽位不同目标的对比效果。
4. **单目标多源覆盖不足与秒级选项断层**：
   每个弹目标的传感器来源仅生成了 3 个，未达到实际预期的 8~10 源（雷达1~4、遥测1~2、光测1~2）；检查器中秒级回溯选项仅支持 15~180 秒，缺失 10 秒及 180~600 秒区间。
5. **规范与代码异味残留**：
   根目录残留临时 Word 文件；交互原型 `prototype.html` 未同步演进；`InstanceCard.vue` 与 `LineProperties.vue` 重复编写了提取唯一目标选项的代码；`TableControl.vue` 中存在单字母命名 `c` 与冗余组件导入。

## 解决方案 (Solution)

针对审查发现的全部问题，本方案制定以下精细化修复与工程整改策略：

1. **滑动窗口自适应毫秒级截取，根除越界**：
   升级 `inWindow` 函数，支持微小时间窗口（放开 1 分钟下限，支持浮点分钟或毫秒级传参，安全下限放宽至 5 秒 / 0.08 分钟），确保提取的数据点完全收敛在坐标轴绘图区（`x >= 58`）内。
2. **严格落实来源权威性（未命中即留白）**：
   重构 `resolveEntityRecord`：当调用方指定了明确的数据源 `source` 时，若未匹配到该数据源的记录，严格返回 `undefined`，绝不静默回退至默认源，保证“图例是哪个源，曲线就是哪个源；无数据即真实留白断线”。
3. **工坊预览状态与持久化契约解耦**：
   将“工坊预览目标”从模板静态持久化属性中剥离，改为工坊运行态的内存级状态（或槽位级独立预览指派），且不写入最终保存的模板 JSON，彻底杜绝污染，同时支持多槽位独立指定预览目标。
4. **演示环境全量供给 12 目标 × 8 传感器完整推流**：
   在 `server/defaults.mjs` 中为每个目标（`P-101` ~ `P-112`）生成全部 8 个测控来源（`雷达1~4`、`遥测1~2`、`光测1~2`）的仿真时序数据，共计 96 条独立传感器轨迹；并在检查器中补齐 10~600 秒回溯选项。
5. **规范整改与代码异味清除**：
   - 将根目录临时文件移动至 `../liteCodeTool_tmp/`；
   - 在 `src/engine/core.ts` 中提取公共纯函数 `extractUniqueTargets(store, schemaType)`，供大屏卡片与工坊检查器复用；
   - 清理 `TableControl.vue` 中未使用的导入与单字母变量名，规范微图弹层失焦关闭；
   - 同步原地演进 `docs/prototypes/prototype.html` 交互原型。

## 用户故事 (User Stories)

1. 作为一名测控大屏指挥员，我想要将折线图设置为 15 秒或 30 秒短周期，以便于观测高动态飞行弹药在最近数十秒内的即时抖动，同时曲线不能越界画到坐标轴外。
2. 作为一名测控指挥员，我想要在为对象 1 指定“光测2”来源而当前光测站尚未捕获目标时，大屏如实显示断线留白而不是悄悄拿雷达数据充数，以便于真实研判各站建链情况。
3. 作为一名大屏设计人员，我想要在工坊中为对象 1 预览 P-101、为对象 2 预览 P-102，以便于在模板制作阶段验证多目标对比布局，且这些试看目标不会被存进模板污染大屏默认配置。
4. 作为一名测控操作员，我想要在大屏下拉框中为 12 个目标中的任意一个自由选择 8 个测控传感器中的任意一个，以便于开展任意站点的交叉比对。
5. 作为一名大屏监控员，我想要在表格中点击查看走势微图后，点击空白处或焦点移出时自动收起浮层，符合直觉交互习惯。

## 实现决策 (Implementation Decisions)

### 1. 时序算法与数据核心层 (`src/engine/core.ts`)

- **滑动窗口纯函数放宽下限**：
  ```typescript
  export function inWindow(points: Point[], now: number, minutes: number): Point[] {
    // 允许最小 5 秒（0.083 分钟），最大 60 分钟
    const safeMinutes = clamp(minutes, 0.083, 60);
    const cutoff = now - safeMinutes * 60_000;
    return points
      .filter((p) => p.timestamp >= cutoff && p.timestamp <= now)
      .sort((a, b) => a.timestamp - b.timestamp);
  }
  ```
- **实体记录解析严格执行来源权威**：
  ```typescript
  export function resolveEntityRecord(
    store: EntityStore,
    type: string | undefined,
    id: string | undefined,
    source?: string,
  ): EntityRecord | undefined {
    if (!type || !id) return undefined;
    const direct = store.get(type, id);
    // 未指定来源时，返回默认直接记录
    if (!source) return direct;
    if (direct && direct.data.source === source) return direct;
    
    // 指定了来源，必须严格匹配该来源；未匹配到必须返回 undefined，严禁回退 direct
    const matched = store.list(type).find(
      (item) =>
        (item.id === id ||
          item.record.data.batch_no === id ||
          item.record.data.vessel_name === id ||
          item.record.data.mmsi === id ||
          item.id.startsWith(`${id}_`)) &&
        item.record.data.source === source,
    );
    return matched ? matched.record : undefined;
  }
  ```
- **提取公共目标去重纯函数**：
  ```typescript
  export function extractUniqueTargets(
    store: EntityStore,
    schemaType: string,
  ): Array<{ id: string; label: string }> {
    const items = store.list(schemaType);
    const seen = new Set<string>();
    const result: Array<{ id: string; label: string }> = [];
    for (const item of items) {
      const targetId = String(item.record.data.batch_no || item.id);
      if (!seen.has(targetId)) {
        seen.add(targetId);
        const name = item.record.data.vessel_name;
        const label = name && name !== targetId ? `${name} · ${targetId}` : targetId;
        result.push({ id: targetId, label });
      }
    }
    return result;
  }
  ```
- **规则引擎操作符收敛**：
  清理正则匹配中未获需求的 `!=` 运算符，严格支持 `>`, `>=`, `<`, `<=`, `..` 及全等匹配。

### 2. 演示推流与底账供给 (`server/defaults.mjs`)

- 为 12 个弹目标（`P-101` ~ `P-112`）生成全量 8 传感器测量底账：
  - 主 ID `P-xxx` 作为首个传感器（如 `雷达1`）；
  - 辅助 ID `P-xxx_src2` 至 `P-xxx_src8` 分别对应其余 7 个传感器（`雷达2~4`、`遥测1~2`、`光测1~2`）；
  - 每个传感器叠加独立的测量离散度与真实传感器误差，提供真实 12 × 8 = 96 条独立数据轨迹。

### 3. 组件与属性面板整改 (`LineProperties.vue`, `CanvasArea.vue`, `TableControl.vue`)

- **秒级窗口选项补全**：
  在 `LineProperties.vue` 中秒级回溯选项补充为 `[10, 15, 30, 60, 90, 120, 180, 300, 600]` 秒；
- **工坊预览目标解耦**：
  将 `workshopPreviewTarget` 从持久化契约 `ControlProps` 中解除保存依赖，在工坊中使用单独的局部状态维护，仅传给 `previewInstance.slotBindings`，保存模板时自动剥离；
- **表格与微图收起**：
  在 `TableControl.vue` 中增加对微图弹层 `focusout` / `blur` 事件的判定，失焦自动收起；重命名 `c` 为 `effectiveCtrl`；移除冗余导入 `LineChart`。

### 4. 资产边界与交互原型同步

- 将工作区根目录的临时 Word 文件移动至同级外部目录 `../liteCodeTool_tmp/`；
- 在 `docs/prototypes/prototype.html` 中原地追加双维度目标切换浮层、微图弹层与消息流控件的原型演示片段。

## 测试决策 (Testing Decisions)

- **良好测试标准**：针对数据过滤截取、时序计算、来源解析等纯函数编写短小、精确的单测，不引入重型端到端 UI 测试；
- **测试覆盖点**（在 `tests/core.test.ts` 中验证）：
  1. `inWindow` 短周期测试：验证 10 秒、15 秒、30 秒等短周期下点位截取的精确度，确认返回点的时间戳严格满足 `timestamp >= now - durationMs`，无 1 分钟外脏点；
  2. `resolveEntityRecord` 严格来源权威：验证指定传感器存在时精确返回，指定传感器不存在时**严格返回 `undefined`**，决不回退默认源；
  3. `extractUniqueTargets` 去重有效性：验证多传感器同批号记录仅提取唯一目标选项；
  4. 规则引擎比较运算符严格按契约匹配。
- **构建验证**：`npm test`（52 项全绿）、`npm run typecheck`（0 错误）、`npm run build`（0 错误）。
