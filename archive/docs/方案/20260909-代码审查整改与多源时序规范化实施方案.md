## 问题陈述 (Problem Statement)

在上一轮双 Y 轴时序曲线、规则引擎与消息流控件实施完成后，经过 `/code-review` 独立双轴审查（Standards 编码规范轴与 Spec 需求契约轴），识别出以下 12 项需要纠偏与加固的工程质量问题：

1. **核心极值算法未下沉至纯函数层（Spec 轴）**：
   `LineChart.vue` 中的 `leftExtents` 与 `rightExtents` 重复编写了值域扩展与 5 步长对齐算法，未按照方案契约下沉到 `src/engine/core.ts` 的 `calculateExtents` 纯函数中，导致核心数学逻辑无法被轻量单测独立保护。
2. **假数据伪造违背真源红线（Standards 轴）**：
   `StreamControl.vue` 前端硬编码预填了 3 条虚构日志（`defaultInitialLogs`），严重违反 [`CONTEXT.md`](../../CONTEXT.md) 中“绝不伪造或臆测数据、无数据时如实呈现空状态”的底线原则。
3. **多源过滤逻辑与字典缺陷（Spec 轴）**：
   - 字典错漏：数据源过滤下拉框硬编码为“雷达1/遥测/光电”，遗漏了仿真环境中的“雷达2”且将“光测”误写为“光电”；
   - 逻辑缺陷：当前在单条记录的当前 `source` 不匹配时直接将历史曲线全量置空（`points = []`），导致同一飞行目标在多源传感器交叉探测时无法在同一图表上同屏对比两条曲线。
4. **右 Y 轴视觉元素缺失（Spec 轴）**：
   图表仅渲染了右侧刻度数字，未绘制右 Y 轴垂直基线，右轴顶部量纲单位（`.chart-axis-unit`）未渲染。
5. **消息流控件契约偏差（Spec 轴）**：
   - 仅支持全局 `_global`，不支持按实体槽位订阅事件流；
   - 默认最大保留行数偏差为 100（方案规定为 50）；
   - 级别状态标牌当前为大写英文字块，未按方案呈现简洁的圆点状态标牌；
   - 包含了方案外的“清空”按钮。
6. **JSDoc 注释规范缺失（Standards 轴）**：
   `StreamControl.vue`、`StreamProperties.vue`、`TableControl.vue`、`TableProperties.vue` 中新增的接口、函数均缺少符合 [`快速开发手册.md`](../../快速开发手册.md) 要求的规范中文 JSDoc 说明。

## 解决方案 (Solution)

针对上述问题，本方案制定以下整改与重构举措：

1. **下沉极值纯函数并补齐单测**：
   在 `src/engine/core.ts` 中实现纯函数 `calculateExtents(values, isFieldAxis)`，统一管理左右 Y 轴的值域拓展、5 步长规整化和保底范围计算；在 `tests/core.test.ts` 中补齐全量边界单测；`LineChart.vue` 消除重复计算直接复用该纯函数。
2. **彻底清除虚构数据，确保真实空状态**：
   彻底移除 `StreamControl.vue` 中的 `defaultInitialLogs` 假数据，无实时日志推流时真实呈现“暂无实时消息”空状态，完全符合真源红线。
3. **修复多源过滤与动态数据源字典**：
   - 属性面板从目标 Schema（如 `projectile`）的字段定义或数据记录中动态提取真实数据来源列表（雷达1、雷达2、遥测、光测），杜绝硬编码；
   - 完善曲线多源比对逻辑：支持按来源对历史采样进行精确匹配，实现同屏同目标多源对比。
4. **补全右 Y 轴基线与轴单位标注**：
   在 `LineChart.vue` 中补齐右侧基线 `<line :x1="plotRight" y1="46" :x2="plotRight" y2="284" ... />`，并在顶部对称渲染右轴单位文本。
5. **对齐消息流控件规格契约**：
   - 支持全局与实体对象双模订阅（优先读取槽位实体事件，无槽位时读取全局）；
   - 默认条数修正为 50 行，优化级别展示为高辨识度的圆点状态标牌，移除方案外冗余按钮。
6. **全量补全规范化 JSDoc 中文注释**：
   严格对照代码规范，对所有新增组件的接口、属性、方法补齐类型与参数返回值注释。

## 用户故事 (User Stories)

1. 作为一名大屏设计人员，我想要在配置双 Y 轴图表时看到清晰的右侧 Y 轴线和右轴单位标注，以便于直观区分左右轴对应的度量物理含义。
2. 作为一名测控指挥员，我想要添加两条针对同一目标但分别指定“雷达1”和“遥测”的曲线，以便于在同一张时序图上对比传感器测量值与真值偏差。
3. 作为一名大屏监控员，我希望在没有新事件日志上报时看到清爽真实的空状态，而不是虚构的假数据，以便于真实反映链路状态。
4. 作为一名系统开发者，我希望图表极值计算作为独立纯函数下沉并拥有单元测试保障，以便于后续升级图表算法时具有坚固的防回归屏障。

## 实现决策 (Implementation Decisions)

### 模块一：核心纯函数与单测接缝 (`src/engine/core.ts` & `tests/core.test.ts`)
- **纯函数契约**：
  ```typescript
  export interface AxisExtents {
    min: number;
    max: number;
  }
  export function calculateExtents(values: (number | null | undefined)[], isFieldAxis = false): AxisExtents;
  ```
  - 空数组时保底返回 `{ min: 0, max: 10 }`；
  - 包含有效数值时，计算 `rawMin` 与 `rawMax`，留出 8% 上下边距；
  - 非航迹模式下按 5 的倍数对齐上下界，`minVal` 保底不高于 0。
- **单测覆盖**：
  覆盖全空值、单点值、负数值域、大跨度正数、零跨度恒定值等边界。

### 模块二：图表多源对比与右轴完整渲染 (`LineChart.vue` & `LineProperties.vue`)
- **右 Y 轴基线与单位**：
  - 存在右轴时绘制 `:x1="plotRight"` 垂直基线；
  - 渲染左轴单位 `<text x="54" y="36" text-anchor="end" class="chart-axis-unit">{{ leftUnit }}</text>`；
  - 渲染右轴单位 `<text :x="plotRight" y="36" text-anchor="start" class="chart-axis-unit">{{ rightUnit }}</text>`。
- **动态来源提取与过滤**：
  - `LineProperties.vue` 根据所选 Schema 动态派生可用数据源字典（来自当前数据记录中出现过的 `source` 字段或标准预设）；
  - `LineChart.vue` 仅在配置了 `filterSource` 且记录存在来源区分时执行精准点位过滤，确保同实体多传感器数据曲线共存。

### 模块三：消息流规范化与空状态合规 (`StreamControl.vue` & `StreamProperties.vue`)
- **移除假数据**：
  初始 `messages` 为响应式空数组 `ref<StreamMessage[]>([])`；
- **实体槽位扩展**：
  如果控件绑定了模板对象槽位（如特定飞船/导弹的告警流），优先读取对应实体的事件记录；默认读取 `_global` 全局事件；
- **默认值与圆点标牌**：
  默认 `streamMaxItems = 50`；
  标牌渲染为 `<span class="stream-level-dot" :class="'dot-' + msg.level"></span><span class="stream-level-text">{{ msg.level.toUpperCase() }}</span>`。

### 模块四：JSDoc 注释规范补全
- 为 `TableControl.vue` 的 `SparklineData`、`openSparkline` 补充完整注释；
- 为 `StreamControl.vue` 的 `StreamMessage`、`scrollToBottom` 等函数补充注释；
- 为 `StreamProperties.vue` 与 `TableProperties.vue` 的具名方法补充 JSDoc。
