# 项目审查发现项整改与契约收敛方案

## 问题陈述 (Problem Statement)

在针对 LiteCodeTool 项目进行全量代码审查（`/code-review`）及第一轮方案访谈后，识别出当前实现与既有业务契约及架构决策之间存在的若干差距与逻辑缺陷：
1. **静态文本就地编辑缺失**：在投屏显示态或大屏编辑态下，用户双击大屏横幅标题或普通静态文本控件时无法像卡片标题一样就地弹出输入框进行文字微调。
2. **逻辑分辨率违背 ADR 0006**：属性检查器中增加了画布逻辑分辨率切换下拉菜单，并在切换时对所有卡片坐标执行了物理缩放重算，破坏了 ADR 0006 确立的“1920×1080 逻辑基准等比矢量自适应”原则。
3. **数据源模式概念漂移与取值缺陷**：代码中引入了非法的 `sourceMode: 'global'` 伪模式，导致核心计算引擎 `resolveValue` 在解析全局宏观统计标量时被误判为静态固定内容，无法正确呈现推流数据。
4. **双轨启动脚本不符合 ADR 0007**：`package.json` 遗漏了离线交付启动命令 `npm run start`，且 `start:vite` 错绑到了开发服务器 `server/dev.mjs`，影响生产环境双轨独立验收。
5. **代码异味重复逻辑**：折线图组件与属性检查器中存在硬编码的重复默认指标与调色板定义。

---

## 解决方案 (Solution)

从用户与架构双重视角实施端到端规范整改与契约收敛：
1. **双通道静态文本就地双击编辑**：为 `ControlRenderer.vue` 中的 `atomic-text` 静态文本控件增加双击就地编辑功能，支持回车/失焦保存与 Esc 取消；对动态绑定的文本严格保持只读，避免与实时推流冲突。
2. **坚守 ADR 0006 矢量等比视口基准**：彻底移除画布检查器中的分辨率切换下拉框与物理坐标重算代码，固定以 1920×1080 为基准逻辑分辨率，由外层视口引擎保障任意高分屏下的无损等比缩放。
3. **回归 CONTEXT.md 静态/动态双模契约**：清理伪模式 `sourceMode: 'global'`，收敛回“静态 vs 动态”两态；全局宏观统计统一作为动态模式下的 `binding.target: 'global'` 分支，修复 `src/engine/core.ts` 中的取值引擎逻辑。
4. **对齐 ADR 0007 双轨构建与启动机制**：补齐 `package.json` 中的 `"start": "node tools/launcher.mjs"`，并将 `"start:vite"` 修正为显式指向 `dist` 生产构建产物目录。
5. **消除重复逻辑，坚持极简主义**：提炼图表默认指标配置与调色板至 `src/engine/core.ts` 共享常量；遵循轻量实用原则，不对现有稳定紧凑的 `src/runtime.ts` 进行过度工程化拆解。

## 用户故事 (User Stories)

1. 作为一名大屏操作员，我想要在投屏显示态下直接双击大屏横幅标题或任意静态文字标签进行错别字修改，以便于无需进入深层面板即可即时调整文案并保存。
2. 作为一名大屏设计者，我希望双击正在实时接收动态推流的文本时不会误触发文本编辑，以便于避免手动修改的内容与后台推送数据发生覆盖冲突。
3. 作为一名大屏设计者，我希望画布始终保持标准的 1920×1080 工业基准排版，以便于投屏到任意 2K、4K 或异形 16:9 屏幕时都能自动等比等宽等高清晰展示，而无需反复重新排版计算。
4. 作为一名大屏设计者，我想要将一个数值控件绑定为“全局数据模式”下的港口宏观指标（如全港在泊船舶总数），以便于大屏可以稳定、实时地从全局指标流中获取最新数值，而不会退化成固定值。
5. 作为一名交付工程师，我想要在断网交付现场运行 `npm run start`，以便于一键启动离线软件包完成现场演示与自检。
6. 作为一名验收测试员，我想要运行 `npm run start:vite`，以便于显式启动经过生产打包（`dist`）的标准产物服务，验证生产构建与开发热更新环境的一致性。

## 实现决策 (Implementation Decisions)

### 1. 静态文本控件双击就地编辑 (`ControlRenderer.vue`)
- 在 `ControlRenderer.vue` 的 `atomic-text` 模板中引入内联编辑状态：
  - 条件约束：仅当 `c.props.sourceMode !== 'dynamic'` 且 `!c.props.clock` 时，允许触发 `@dblclick`；
  - 交互行为：双击进入编辑态，渲染 `<input class="inline-title-input">` 并自动聚焦全选，按 `Enter` 提交、`Esc` 放弃、`blur` 保存；
  - 数据同步：调用统一的属性更新函数写入 `control.props.staticValue`，并在大屏状态下触发 `checkpoint()` 记录撤销栈与标记未保存状态。

### 2. 画布配置收敛与 ADR 0006 对齐 (`Inspector.vue`)
- 移除 `Inspector.vue` 中的 `screenResolution` 函数以及相关的大屏组件坐标等比物理重算循环；
- 移除画布配置栏中的 `<select aria-label="逻辑分辨率">` 下拉框；
- 保留说明文案：“固定 1920×1080 标准基准；投屏自动等比适配视口，非 16:9 屏幕保留必要留白，不裁切业务内容”。

### 3. 数据源模式契约规范化与引擎修复 (`types.ts`, `core.ts`, `Inspector.vue`, `LineChart.vue`)
- **类型契约收敛 (`src/types.ts`)**：
  - `ControlProps.sourceMode` 定义恢复为 `'static' | 'dynamic' | undefined`；
  - 全局数据绑定严格通过 `Binding.target = 'global'` 与 `Series.target = 'global'` 表达。
- **核心计算引擎修复 (`src/engine/core.ts`)**：
  - 修正动态判定：
    ```typescript
    const dynamic = c.props.sourceMode === 'dynamic' || (!c.props.sourceMode && !!c.binding);
    ```
  - 确保当 `c.binding?.target === 'global'` 时，正确通过 `store.get(type, '_global')` 提取对应全局数据字段与更新时间戳。
- **组件与检查器适配 (`LineChart.vue`, `Inspector.vue`)**：
  - 折线图将“监控对象槽位”与“全局统计指标”的判定逻辑收敛为依据曲线系列中的 `series.target === 'global'`；
  - 检查器在为折线图切换全局/槽位模式时，统一写入 `sourceMode: 'dynamic'`，并通过系列属性设置 `target: 'global'`。

### 4. 双轨启动脚本修复 (`package.json`, `tools/launcher.mjs`)
- 在 `package.json` 的 `scripts` 中补齐/修正启动命令：
  - `"start": "node tools/launcher.mjs"`（默认启动离线包）；
  - `"start:demo": "node tools/launcher.mjs"`；
  - `"start:vite": "node tools/build.mjs --preview"`（或者设置 `CLIENT_DIR` 指向 `dist` 运行 `server/index.mjs`）；
  - 保留 `"dev"` 与 `"dev:demo"` 专门调用 `server/dev.mjs` 进行日常热更新开发。

### 5. 提取图表常量与消除异味 (`src/engine/core.ts`)
- 在 `src/engine/core.ts` 中导出公共图表常量：
  - `DEFAULT_CHART_COLORS = ['#22D3EE', '#25D8AE', '#FFBF47', '#38ACD1']`；
  - `DEFAULT_GLOBAL_CHART_FIELD = 'total_vessels'`；
  - `DEFAULT_SLOT_CHART_FIELD = 'speed'`；
- `LineChart.vue` 与 `Inspector.vue` 统一从 `core.ts` 导入该常量，消除代码异味。

## 范围外说明 (Out of Scope)

1. **不引入非 16:9 画布自定义分辨率配置**：根据 ADR 0006，不支持任意自由分辨率画布，全部统一采用 1920×1080 等比缩放视口。
2. **不对 `src/runtime.ts` 进行大面积文件拆分**：鉴于目前项目代码量精简且架构稳定，坚决杜绝过度治理。
3. **不在未获明确授权下执行 Git Commit**：所有实施变更严格保留在工作区等待用户指示。
