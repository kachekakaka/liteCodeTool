# 高度度量、多来源接入与旧数据升级修复方案

日期：2026-09-09

状态：已实施并验证，完成日期 2026-09-09。

验证结论：63 项核心单测、类型检查、统一生产构建、改动文件格式检查通过。源码开发服务与发布服务完成启动、bootstrap、96 条飞行来源记录的真实 HTTP 接入、来源查询、旧单位持续换算、导入及保存兼容验证；浏览器完成高度与速度双轴、目标来源同步、缺失提示、撤销重做、保存恢复、工坊临时预览及消息流实例隔离验证。默认真实和演示数据目录均已升级并保留原文备份；真实目录未注入演示实体。

审查修订：旧单位转换同时维护接入端单位配置；旧来源空值通过大屏 bindingVersion 区分并标准化，覆盖旧目录、导入和新配置保存重开。

实施定向检查补充：将“搜索更多对象”抽屉也纳入目标排重和来源选择；共享槽位的新建、改名、删除限制在工坊，避免实例编辑污染模板；演示全局消息移除实体 ID；首次资源补缺纳入升级校验顺序，冲突时不提前写入缺失模板。这些均用于闭环本方案既定身份、实例隔离与冲突保护要求。

## 1. 目标与问题依据

修复提交 `60b4209` 相对 `07c697c` 引入或未闭环的问题，使已有安装环境能够使用高度度量，并使大屏画布弹层、右侧编辑面板和真实多来源数据接入一致工作。

用户提供的 Word 原始要求为：大屏画布切换曲线监控目标时提供数据来源选择；画布切换目标与大屏右侧编辑栏保持一致；折线 Y 轴支持高度/km，速度使用 km/h。这里的右侧编辑栏指大屏编辑面板，不能以增加组件工坊预览目标代替。

本轮检查依据与结果：

| 编号 | 已确认问题 | 直接证据 |
| --- | --- | --- |
| R1 | 仅增加内置模式，已有环境没有升级 | 本机默认真实、演示目录均只有 vessel、port_stats；服务启动时 seed 不更新已有文件 |
| R2 | 大屏两处目标选择仍不一致 | 画布弹层按批号排重，右侧 InstanceProperties 仍列原始记录且没有来源选择；新示例分别出现 12 与 96 个选项 |
| R3 | 多来源示例不能按相同格式通过真实接入 | 记录 id 使用 P-101_src2 等后缀，batch_no 仍是 P-101；当前接入校验要求两者相同，96 条示例有 84 条被拒绝 |
| R4 | 消息流忽略实例私有属性覆盖 | 父组件传入原始 control，StreamControl 未合并 controlOverrides |
| R5 | 工坊临时预览目标被持久化 | 选择器写入模板 props，保存与导出未剥离该字段，与界面提示相反 |

检查基线为工作区干净、52 项现有单测通过、类型检查通过；定向检查发现 6 个改动文件格式不合规。以上为本次调查结果，不等同于浏览器交互或真实接入全链路已验收。

## 2. 范围与原则

- 处理 R1～R5，并格式化实际涉及的自有源码；不扩展消息流、表格、图表的新功能。
- 保留用户现有大屏、模板、数据和自定义模式，不通过删除整个数据目录或覆盖全部默认配置修复问题。
- 飞行目标提供高度/km、速度/km/h；船舶仍保持既有航速度量。默认基础曲线仍可以从船舶开始，但模式切换入口和字段归属须清晰。
- 保持统一 Vite 构建、源码与用户数据隔离、实例覆盖隔离等现有规则；不新增状态管理框架、数据库或重型测试体系。
- 技术细节由本方案及后续契约维护；业务术语以 [CONTEXT.md](../../../CONTEXT.md) 为准，现有取舍查阅 [ADR 0013](../../../docs/adr/0013-dual-dimension-target-retargeting-and-table-rule-truth.md)。实施时修正其中对“大屏右侧编辑栏”和“工坊预览”的混淆，不另建重复 ADR。

## 3. R1：已有数据目录的兼容升级

### 3.1 升级位置与写入边界

新增轻量数据升级模块，在服务取得当前数据目录锁后、读入 schemas 和实体池并开放接口前执行。仅处理当前启动所指定的 DATA_DIR；演示目录与真实目录分别处理，不扫描或改写其他目录。

升级过程先读取并计算变更，校验全部候选结果，再备份和写入；复用已有 JSON 原子写入方式，不新增数据库迁移框架。需要修改的原文件备份到当前持久化数据目录下的专用升级备份子目录，保留原文、版本与本次变更清单。实施验证日志仍放仓库同级临时目录，备份不能放进源码仓库。

涉及多文件单位转换时，必须有可恢复的执行记录：只有整批完成才记录成功；中断重启后先恢复到一致状态再重试，不能依据已经改写的单位再次换算数值。升级成功后再次启动不得重复转换、覆盖配置或追加重复演示记录。

### 3.2 按已有内容合并

| 已有状态 | 拟处理方式 |
| --- | --- |
| 缺少 projectile 或 event_log | 补入缺失内置模式，保持原有模式、顺序和自定义字段 |
| 已有兼容的 projectile 模式 | 补齐缺失的内置字段与身份元数据；保留用户显示名称、自定义字段和来源选项，内置来源仅补缺失项 |
| 可识别的旧内置 projectile 使用 m、m/s | 作为同一批升级处理元数据、已有快照数值及明确绑定这些字段的单位相关配置；高度除以 1000，速度乘以 3.6，null 与字段时间戳不变 |
| 自定义单位、字段类型冲突或不能确定含义的旧配置 | 保留原文并列出具体冲突及受影响对象；不只改单位标签、不猜测数值单位，不把冲突状态宣称为已升级完成 |

单位相关配置包括明确绑定对应字段的数值阈值、区间、静态度量值和显式单位覆盖；仅转换可以确定归属和语义的数值。无法安全解析的表达式进入冲突清单，不对所有数字做文本替换。船舶航速与其他同名 speed 字段不受影响。遇到本批必需项的冲突时停止本批写入并输出处理说明，防止半完成升级后继续提供错误度量。

模板遵守保留用户修改原则：补入缺失内置模板，对可识别旧内置表格仅补缺失的默认列颜色配置，保留明确清空或自定义规则。未能确认是默认值的内容不覆盖。既有大屏的布局、实例私有样式和模板引用保持不变。

持续接入通过数据目录内 `ingestion-units.json` 显式配置 projectile 默认输入单位及按 source 的覆盖；旧 m/m/s 环境升级时将旧输入单位与快照转换作为同一批写入，后续 HTTP 增量在接入边界转为 km/km/h。新环境默认接收 km/km/h，演示生成与已规范化快照不重复转换。采集端改为新单位后须同步修改对应来源配置并重启服务，不根据数值大小猜测单位。

### 3.3 演示数据与真实数据分开

- 演示环境仅补齐缺失的飞行目标/来源组合和必要消息模式初始记录，保留已有记录；使用与真实接入相同的身份规范进行校验和初始化。
- 真实环境补模式与兼容元数据，不注入飞行目标或消息演示数据。
- 历史点仍遵循当前内存缓冲契约，快照不得伪造过去的曲线历史。

## 4. R3：业务目标与来源记录分离

### 4.1 拟采用的最小协议修正

保持现有 `Envelope.type + Envelope.id` 作为实体池记录键，不整体改写实体池结构。业务目标与来源通过字段表达：

| 概念 | 飞行目标示例 | 用途 |
| --- | --- | --- |
| 记录标识 Envelope.id | P-101、P-101_src2 | 唯一定位某一来源的数据记录，用于接入、快照和增量合并 |
| 业务目标 batch_no | P-101 | 大屏目标候选、槽位指派与多来源归组 |
| 数据来源 source | 雷达1、雷达2 | 选择同一业务目标的某条观测记录 |

Schema 增加可选的业务目标字段与来源字段元数据（拟命名 `targetIdField`、`sourceField`）。projectile 声明 batch_no 与 source，不再将 batch_no 声明为必须等于记录 id 的 `idField`；vessel 保持原有 mmsi 与 id 一致的校验。具体来源不限于内置 8 个名称，不禁止用户实际接入的新来源。

外部单源旧包仍可使用 `id=P-101、batch_no=P-101`。多源包使用互不冲突的记录 id，业务批号可以相同；不能让两种来源持续复用同一个 id，相互覆盖历史。首次建立多来源记录应提供目标和来源字段，后续部分字段增量可继承已有身份。

### 4.2 统一校验与解析

- 抽出接入校验/标准化纯逻辑，让 HTTP 接入、演示生成和相应单测调用同一实现，不在测试中复制一份校验器。
- 允许多来源记录 id 与业务批号不同，同时校验字段类型、有效标识和源时间。已经建立的记录不得悄悄改绑另一业务目标或来源；同一目标与来源对应多条冲突记录时明确报错，不按列表顺序随意选择。
- 目标候选和记录解析使用同一身份规则，不依赖 `startsWith` 猜测归组。兼容旧后缀记录时，优先使用记录实际 batch_no/source，不根据后缀序号推测来源。
- 快照、WebSocket、HTTP 单记录查询与 `retarget` 底账读取保持记录身份一致。槽位中的业务目标加来源先解析为记录 id，再请求对应底账；无该来源时显示缺失，不错误读取另一来源。
- 如果只有同一 id 下交替上报来源造成的旧混合快照，无法还原历史来源，应明确列为不兼容输入，不伪造多来源历史。

## 5. R2：统一大屏两处目标与来源选择

### 5.1 共用数据和操作

画布 InstanceCard 弹层与大屏右侧 InstanceProperties 共用目标候选、来源候选、当前选择解析与槽位改绑函数。可提取一个职责单一的组合式函数或小型选择组件，不复制两套下拉框业务逻辑。

- 目标列表按业务目标排重；12 个目标、每目标 8 个来源仍显示 12 个目标，来源单独选择。
- 两处均读写同一实例的 slotBindings 与 slotSourceBindings，任何一处切换后另一处立即同步，撤销、恢复最近保存指派及保存重开保持一致。
- 旧 slotBindings 若存的是来源记录 id，能查到完整身份时转换为业务目标加来源；暂时缺少底账时保留原值并标明待解析，不能静默解绑。
- 选定来源不存在时保留该选择并提示暂无数据，不能自动切到其他传感器。
- 更换目标时保留原来源意图；新目标没有该来源则显示缺失。一次“目标＋来源”变更只生成一次撤销记录，异步底账返回不能覆盖后续选择。

### 5.2 消除“全部/自动”的歧义

折线一条序列始终对应一条来源记录，不把多来源历史混成一条曲线。下拉框明确区分：

- 跟随曲线配置：槽位不设来源覆盖，曲线可沿用自身 filterSource；其他控件没有来源配置时采用自动选择。
- 自动选择：槽位明确要求忽略曲线的来源过滤，选择该目标的一条确定记录；优先取记录 id 与目标 id 相同的有效记录，否则按稳定记录顺序选取，并展示实际来源。
- 具体来源：槽位明确来源优先于曲线配置；未命中时显示无数据。

利用现有 slotSourceBindings 区分“键缺失”和“显式空值”，不引入第二份来源状态。兼容旧空值含义，并更新选择器文案，避免显示“全部”却只取一个来源。

大屏新增 `bindingVersion: 2` 兼容标记：无标记的旧配置将空字符串来源删除，保留原来的“跟随曲线”行为，再标记为 2；版本 2 中空字符串才表示显式自动。旧目录升级、旧文件导入和加载标准化共用该规则，新保存/导出保留标记，重开不再次转换。

### 5.3 高度字段的可发现性

保持既有模式过滤，不能把高度硬塞进船舶模式。在折线配置中清晰显示当前数据模式，并说明高度/km 与速度/km/h 属于飞行目标。切换为飞行目标后立即提供正确字段和对象槽位；保留仍有效的曲线颜色、名称和左右轴归属，清理不兼容字段与来源，不无故把右轴重置为左轴。

## 6. R4：消息流采用有效实例属性

统一使用模板和 controlOverrides 合并后的有效控件；只在一个明确层级执行合并，避免部分属性读模板、部分属性读实例。

- 大屏中修改最大保留条数、自动滚动和数据模式立即影响当前实例，其他实例及模板不变。
- 调低条数时立即裁剪已有缓冲，而非每来一条只删一条使超限数量长期不变。
- 切换数据模式时清空原模式缓冲与去重标记，不能把两个模式的消息混在一起；恢复覆盖后采用恢复后的配置。
- 仅修复属性覆盖及由此触发的缓冲行为，不借本次加入消息历史持久化或改造通用事件流协议。

## 7. R5：工坊预览状态独立于模板

预览选择放入工坊会话的临时状态，按模板、控件和槽位确定作用范围，不再写入 ControlProps。

- 预览目标和来源只影响相关控件/槽位，不把第一个曲线的目标广播给整个模板所有模式的槽位。
- 普通离开工坊再返回同一草稿可保留会话预览；切换模板或新建草稿时重置相应预览状态。刷新后恢复默认预览，不要求持久化。
- 改预览不触发模板脏标记、不要求保存、不进入导出模板或实例覆盖。
- 对旧数据中的 workshopPreviewTarget 在载入标准化和保存/导出边界剥离；可以作为本次会话初值读取，但不能再次写回。不要靠清空其他用户属性达到剥离目的。
- 显示态和大屏编辑态始终使用实例指派，不能读取工坊临时目标。

## 9. 实施顺序

1. 再次核对当前 HEAD、工作区及既有数据形态，确认本方案基线尚适用；只读取用户数据，先在隔离副本完成复现。
2. 先修正共享身份与接入校验，形成旧单源、同目标多来源、冲突来源及快照查询的针对性测试。
3. 实现旧数据升级和兼容读取，在旧目录副本验证幂等、单位转换、冲突保留及中断恢复；再接入启动顺序。
4. 统一画布与右侧面板的候选和改绑操作，验证双向同步、来源缺失、撤销与保存恢复；补齐高度字段提示。
5. 修复消息流属性覆盖与工坊预览状态，统一导入导出兼容边界。
6. 更新原型、长期文档与发布装配；格式化本次修改文件并运行对应检查。
7. 完成下一节验收，记录证据及无法完成的项目；未通过项不得凭测试数量或演示截图标记为已解决。

## 10. 验收标准

### 核心和升级验证

- 仅包含 vessel、port_stats 的旧数据副本升级后，bootstrap 出现飞行目标及正确度量字段；原有自定义模板、大屏、用户模式和无关快照保持不变。真实目录不出现模拟实体。
- 同一数据副本连续启动两次，不重复演示实体、不再次换算数据、不反复改写已升级文件。
- 用已知数值验证旧内置 m/m/s 升级：1000 m → 1 km，10 m/s → 36 km/h；明确关联的阈值一致转换；未知单位/表达式冲突不发生部分写入。中断恢复不造成二次换算。
- 96 条新演示飞行记录全部通过与 HTTP 相同的校验实现；同一批号、不同记录 id 和来源的历史互不覆盖；旧单源仍可接入，复用记录 id 改变身份明确拒绝。
- 目标列表排重和来源解析测试覆盖同批多源、无主记录、指定来源缺失、旧后缀绑定、记录身份冲突及空值覆盖语义。
- 验证旧单位升级后继续接收旧单位来源的增量，数值仍正确；按来源覆盖为新单位时不重复换算。旧来源空值导入仍跟随曲线，新版本自动选择保存重开后保持自动。
