## 问题陈述 (Problem Statement)

用户在进行测控大屏实测体验时，指出了以下 3 项核心阻碍指挥调度与模板制作的工程与设计问题：

1. **度量量纲与模板绑定脱节**：
   组件工坊默认的曲线模板绑定的是海事船舶（`vessel`），导致新建曲线时 Y 轴度量仅有“航速/节、航向/°、经度、纬度”，用户误以为折线 Y 轴度量不支持“高度/km”和“速度/km/h”；此外，系统内置的飞行目标（`projectile`）模型中高度单位仍为 `m`（米），速度为 `m/s`（米/秒），未对齐指挥测控现场的标准工程量纲（km 与 km/h）。
2. **监控对象与数据来源（12 目标 × 8~10 源）两端不对称**：
   大屏运行态的就地“切换监控对象”浮层目前仅能切换目标实体（批号/MMSI），无法切换数据来源（雷达/遥测/光测）；而在组件工坊编辑栏中，仅能为单条曲线静态指定数据源过滤，却无法选择预览目标实体。两端操作割裂，导致指挥员在多源传感器交叉探测同一飞行目标时无法在大屏上灵活进行同屏同目标、跨传感器的即时对比。
3. **表格颜色“所见与所配”脱节**：
   `TableControl.vue` 中遗留了写死的 `statusClass` 样式代码（将 `status` 字段硬编码上色），而模板的 `tableColumnRules` 规则配置数组实际为空。导致表格在界面上渲染了彩色状态，但右侧检查器却显示“未配置过列状态颜色规则”，用户无法查看或修改规则，违背了“一项事实一个真源”的低代码原则。

## 解决方案 (Solution)

针对上述问题，本方案制定以下规范化与真源化重构举措：

1. **规范飞行目标物理量纲**：
   将 `projectile` Schema 字段定义标准升级为 `altitude: 高度 (km)`、`speed: 速度 (km/h)`；工坊基础模板保持海事船舶不变，用户在右侧属性栏将 Schema 切换为“飞行目标”后，Y 轴度量字段即刻提供规范的高空高速度量指标。
2. **双维度目标重定向与严格槽位来源权威**：
   - 在大屏运行态“切换监控对象”浮层中，为每个槽位（对象 1、对象 2 等）提供两级联动下拉框：【目标实体（如 P-101）】与【数据来源（如 雷达1、遥测1 等）】；
   - 确立大屏槽位来源的绝对权威：一旦大屏运行时指定了槽位数据来源，该槽位下的曲线强制按所选来源过滤展示；
   - 组件工坊编辑栏对称补齐“预览目标”下拉框，允许设计人员在工坊内指定特定目标查看演示效果。
3. **12 目标 × 8 数据来源的连续仿真支撑**：
   在演示环境（`--demo`）的 `demoEnvelopes` 中生成 `P-101` 至 `P-112` 共 12 个飞行弹目标，覆盖 `雷达1`~`雷达4`、`遥测1`~`遥测2`、`光测1`~`光测2` 共 8 个真实测控站来源，推流连续平滑的动力学航迹数据。
4. **表格列颜色 100% 规则真源化**：
   彻底移除 `TableControl.vue` 中的 `statusClass` 硬编码；在内置表格模板中显式注入初始 `tableColumnRules`；检查器面板优先展示已有规则列，实现“界面呈现完全等于面板配置”。

## 用户故事 (User Stories)

1. 作为一名大屏设计人员，我想要在为图表选择“飞行目标”模式时看到“高度 / km”与“速度 / km/h”度量字段，以便于直接构建符合空天防空测控规范的时序监控卡片。
2. 作为一名测控指挥员，我想要在大屏运行态的“切换监控对象”浮层中同时选择弹目标（如 P-101）与传感器来源（如 雷达1），以便于针对特定雷达站的跟踪质量进行重点监视。
3. 作为一名测控指挥员，我想要将对象 1 设为“P-101 + 雷达1”、对象 2 设为“P-101 + 遥测”，以便于在同一张双 Y 轴时序图上同屏比对雷达测量值与遥测真值的系统误差。
4. 作为一名组件设计人员，我希望在组件工坊编辑曲线时能下拉选择具体弹目标（如 P-102）进行试看，以便于在制作模板阶段就能验证真实波形与样式。
5. 作为一名大屏监控员，我希望在大屏运行态切换了槽位数据来源后，图表能强制以此来源为准刷新，避免被模板设计时的静态来源配置所干扰。
6. 作为一名大屏配置人员，我想要在检查器中直接查阅和修改表格“航行状态”或“拦截状态”的颜色规则，而不是看到一片空白，以便于自主调整告警阈值与色值。

## 实现决策 (Implementation Decisions)

### 1. 数据模型与仿真推流层 (`server/defaults.mjs`)
- **Schema 度量变更**：
  ```javascript
  {
    type: 'projectile',
    name: '飞行目标',
    isEntity: true,
    idField: 'batch_no',
    fields: [
      { key: 'batch_no', name: '批号', type: 'string' },
      { key: 'source', name: '数据源', type: 'enum', options: ['雷达1', '雷达2', '雷达3', '雷达4', '遥测1', '遥测2', '光测1', '光测2'] },
      { key: 'altitude', name: '高度', type: 'number', unit: 'km', precision: 2 },
      { key: 'speed', name: '速度', type: 'number', unit: 'km/h', precision: 0 },
      // ... 经纬度、航向、状态
    ]
  }
  ```
- **12 目标 × 8 测控源底账与推流**：
  - `demoEnvelopes` 生成 12 个弹目标（`P-101` ~ `P-112`）；
  - 每个目标分配多个传感器数据源（`雷达1~4`、`遥测1~2`、`光测1~2`）；
  - 高度范围设置为 10.0 ~ 120.0 km，速度设置为 1200 ~ 5400 km/h；
  - 模拟推流定时器持续按各传感器真实刷新率输出增量时序。
- **表格模板默认规则显式注入**：
  在 `tpl_table` 与 `atom_table` 的 `props` 中显式注入初始 `tableColumnRules`：
  ```javascript
  tableColumnRules: [
    {
      field: 'status',
      rules: [
        { value: '在航', color: '#22C55E' },
        { value: '巡航', color: '#06B6D4' },
        { value: '作业', color: '#F59E0B' },
        { value: '告警', color: '#EF4444' }
      ]
    }
  ]
  ```

### 2. 契约定义与校验核心层 (`src/types.ts` & `src/engine/core.ts`)
- **实例扩展槽位来源映射契约**：
  ```typescript
  export interface ComponentInstance {
    // ...
    slotBindings: Record<string, string>;
    /** 槽位数据来源绑定：slotId -> source 名称；未设置或空字符串表示全部/自动 */
    slotSourceBindings?: Record<string, string>;
  }
  ```
- **契约校验更新**：
  `validateScreen` 校验允许合法的 `slotSourceBindings` 映射，确保保存大屏时通过模式校验。

### 3. 大屏运行态双维度切换交互 (`src/components/ControlRenderer.vue`)
- **就地换船/换目标浮层重构**：
  - 浮层中对每个槽位（`slot_1`, `slot_2` 等）渲染行内两级下拉框：
    - 左侧：目标实体选择（从当前 Schema 实体列表中提取 MMSI 或 批号，支持展示名称与批号）；
    - 右侧：数据来源选择（根据当前实体或当前 Schema 提取已上报的可用来源列表，如 `雷达1`、`遥测1` 等，首项为 `全部/自动`）；
  - 用户更改来源时，通过 `slotSourceBindings` 更新组件实例，并触发图表重绘。

### 4. 曲线时序控件与编辑栏对称联动 (`LineChart.vue` & `LineProperties.vue`)
- **严格槽位来源过滤生效**：
  - 在 `LineChart.vue` 提取序列数据时：
    `const activeSource = props.instance.slotSourceBindings?.[seriesItem.slotId ?? ''] || seriesItem.filterSource;`
  - 若 `activeSource` 存在且非 `全部`，强制按该来源匹配目标历史点对，不再受设计态静态值制约。
- **工坊设计态预览目标选择**：
  - 在 `LineProperties.vue` 中新增“工坊预览目标”下拉框；
  - 设计人员在工坊中选定目标后，工坊预览画布以该选定目标作为 `slotBindings` 渲染真实历史波形。

### 5. 表格列状态颜色真源化 (`TableControl.vue` & `TableProperties.vue`)
- **剥离硬编码样式**：
  删除 `TableControl.vue` 中的 `statusClass` 函数与 `column.key === 'status' ? statusClass(...) : ''` 绑定；单元格颜色 100% 交由 `getCellStyle(row, column)` 经规则引擎计算；
- **属性面板智能联动**：
  在 `TableProperties.vue` 中，初始化选中列时优先选择在 `tableColumnRules` 中已有规则的列（如 `status`），使得用户点击检查器时直接看到预置的 4 条状态颜色规则并可原地修改。

## 测试决策 (Testing Decisions)

- **良好测试标准**：遵循轻量实用主义，针对纯函数算法、数据契约校验与双维度映射开展严格单测，严禁引入重型端到端 UI 测试；

  2. 多源同目标轨迹过滤解析：验证给定批号在指定具体传感器源时能够精确提取对应点集；
  3. 表格规则引擎回归：确保 `evaluateColorRule` 在全等匹配与区间匹配下对状态文字解析稳定；
- **构建与回归**：执行 `npm test`（全量单测全绿）与 `npm run build`（0 警告打包发布）。
