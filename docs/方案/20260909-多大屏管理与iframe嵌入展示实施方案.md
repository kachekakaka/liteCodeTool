| 项目 | 结论 |

2. **切换的保存方式**：嵌入页切换只影响当前页面，刷新恢复该大屏保存的默认目标与来源；管理端负责保存默认配置。

## 2. 当前实现与改动落点

当前并非只能存储一份大屏：`src/stores/screens.ts` 已支持创建、列出、载入、保存多份配置；后端按大屏 ID 分文件持久化。已有 `/screens/:screenId/edit` 与 `/screens/:screenId/view` 两种独立地址。因此沿用现有资源模型，补齐管理入口和嵌入体验。

需要处理的具体缺口：

- 缺少管理页及重命名、复制、删除的完整操作流程。
- `/api/bootstrap` 固定读取 `screen_main`，服务启动也会补建它；直接增加删除功能会导致初始化失败或删除后重新出现。
- 发布服务统一设置 `frame-ancestors 'none'`，当前页面不能被 iframe 加载。
- 现有展示页保留返回编辑器、保存、文字编辑等入口；快捷键也能触发保存和回到编辑器。只隐藏导航不足以形成正确的嵌入交互。
- 相同大屏 ID 的页面切换会复用内存草稿；嵌入入口需要明确载入已保存配置，避免把编辑器尚未保存的内容带进集成页面。

另有活动中的[局域网访问与组件工坊交互修正方案](20260908-局域网访问与组件工坊交互修正方案.md)。局域网监听、Host/Origin、接入凭据和启动地址输出以该方案为真源。本次不复制其实施内容；开始实施前核对实际合入状态，iframe 专项验证使用可达的服务地址。若联合实施，访问相关改动只做一次，分别记录验收结果。

定向审查修订：当前局域网访问前置条件尚未实现，本次一并完成与嵌入直接相关的开发/发布监听及 Host/Origin 访问支持；不连带实施组件工坊界面或接入凭据改造。验收必须区分本机跨端口、通过局域网地址访问和另一台内网电脑实测。无法取得另一台电脑时保留该项待验收，不将本机结果当成跨机结果。

## 3. 大屏管理与资源边界

### 3.1 管理页面

新增 `/screens` 管理页，工作区导航增加“大屏管理”。无显式资源的根地址 `/` 进入管理页；旧 hash 和 `?screen=...` 地址优先按原规则转换，已有明确的大屏编辑、展示地址继续有效。

采用简洁列表，展示名称、资源 ID 和操作入口，支持按名称查找。新建、重命名、复制和删除使用页面内表单；涉及当前脏草稿时明确勾选放弃或取消返回保存。不增加缩略图生成、分组权限或发布审批系统。新建后进入该大屏编辑器；空列表展示“新建大屏”入口。

| 操作 | 拟议行为 |
| --- | --- |
| 新建 | 输入名称，创建独立 ID 的空白大屏，保存成功后进入编辑器。 |
| 重命名 | 只修改名称，保持 ID、内容及集成地址不变；拒绝空名称。 |
| 复制 | 复制源大屏的已保存内容，生成新的大屏 ID 和组件实例 ID；用户输入副本名称。 |
| 删除 | 显示大屏名称并确认，只删除该大屏配置；允许删除最后一份。 |
| 编辑、预览 | 分别进入编辑地址和现有展示地址；加载失败显示对应资源错误。 |
| 复制地址与代码 | 提供独立展示地址、嵌入地址及 iframe 代码；复制失败时提供可选取的文本。 |

名称不是资源身份，可重复，列表同时显示 ID 以便区分。复制保留布局、实例覆盖与默认目标/来源，继续引用原有共享模板，不调用会复制模板的导入流程。

### 3.2 独立与共享的含义

每份大屏独立保存画布、组件实例、实例覆盖、默认监控目标与来源。模板库、模式和实时实体池沿用平台共享机制；修改共享模板仍会影响引用它的大屏。删除大屏不删除模板、实体或其他大屏。

管理页不维护第二套大屏编辑草稿。操作当前脏草稿对应的资源时，必须先处理未保存内容：取消操作保持原页面和草稿；保存成功或明确放弃后才继续。复制以已保存内容为准，不静默丢弃或夹带未保存的修改。

## 4. 持久化、接口与路由

### 4.1 复用现有配置格式

沿用按 ID 保存大屏 JSON 的方式和现有 `bindingVersion: 2` 语义，不新建数据库或批量重写用户配置。来源键缺失、空串、指定名称的含义保持一致，复制时保留这种区别。

列表使用现有资源列表接口；新建与复制使用现有创建接口。重命名先读取完整配置及 ETag，修改名称后通过现有条件保存接口提交，不用过期的前端缓存覆盖其他字段。

重命名成功后，若该 ID 是当前大屏，同时应用服务端返回的完整配置、保存基线和新 ETag，并重置旧撤销记录；失败不提前修改本地名称或版本。验收覆盖“重命名→返回编辑→修改内容→再次保存”。

新增 `DELETE /api/screens/:screenId`，携带读取时的 `If-Match`：

- 成功返回 `204`；不存在返回 `404`；版本冲突返回 `412`；缺少必要版本条件返回 `428`。
- 删除与保存共享按资源文件串行执行的队列，版本检查和删除在同一个任务中完成。
- 失败不先移除列表行；成功后更新列表、清理对应的当前资源状态和上次访问记录。
- 其他窗口继续保存已删除资源时明确失败，不能将旧草稿重新创建为同 ID 大屏。

### 4.2 默认大屏与空集合

移除启动时无条件补建 `screen_main` 的行为。全新目录仍通过现有一次性初始化/升级流程创建初始大屏；已完成初始化的目录允许没有 `screen_main`，也允许没有任何大屏。不删除或重置现有升级标记，不重复执行单位换算。

调整 `/api/bootstrap`：返回实际大屏列表，默认大屏优先选择现存的 `screen_main`，否则按 ID 排序选择第一份；没有大屏时返回 `screen: null`。同步初始化类型、store 和路由，使模式、模板、实体池及实时连接仍可正常初始化，管理页可以创建第一份大屏。

所有默认或上次访问候选都先验证是否存在。无明确 ID 的兼容入口 `/viewer` 在有大屏时选择有效候选，无大屏时转管理页；明确指定但已删除或不存在的 ID 显示错误，不能悄悄展示其他大屏。

### 4.3 地址约定

| 地址 | 用途 |
| --- | --- |
| `/screens` | 大屏管理 |
| `/screens/:screenId/edit` | 大屏编辑，保持已有地址 |
| `/screens/:screenId/view` | 独立展示，保持已有地址 |
| `/screens/:screenId/embed` | 供其他系统嵌入的交互展示 |

嵌入路由复用展示视图，以明确的 `embedded` 路由标记控制交互，不复制一套画布或数据加载实现。保留现有加载取消和响应序号保护，快速切换资源时旧响应不得覆盖新目标。

## 5. iframe 交互与集成

本节按“切换只在当前页面生效”设计。

- 嵌入页展示画布、实时状态、监控目标及来源切换入口，复用现有目标搜索、单来源/多来源选择和缺失数据反馈。
- 不显示管理导航、返回编辑器、配置保存和文字管理入口；卡片双击标题也不进入编辑。全屏入口可以保留，随 iframe 的全屏授权工作。
- 嵌入页面的目标和来源切换只保存在当前页面内存中，不写回大屏 JSON，也不写入跨窗口共享的本地存储。两个 iframe 即使打开同一大屏，也各自维护选择；刷新重新加载已保存默认值。
- 沿用当前页面的实例状态执行切换，通过嵌入上下文统一控制保存和离开行为，不再创建全局集中状态模块。嵌入页的临时切换不显示“未保存”、不触发关闭页面的草稿提示；`Ctrl+S` 不保存，`Esc` 只关闭当前浮层，不跳到编辑器。
- 从编辑上下文进入嵌入上下文时先处理已有脏草稿，再重新载入该 ID 的已保存配置；从嵌入上下文离开时清理临时指派。不能仅凭 ID 相同跳过加载。
- 指定来源缺失时明确显示缺失状态，不回退到其他来源；底账继续按实际记录身份及逐字段时间合并，晚到数据不能覆盖较新数值，路由资源装载保留请求取消和过期响应保护。
- 画布按 iframe 自身容器尺寸适配，通过现有尺寸观察与缩放能力响应容器变化，不读取父页面 DOM。

复制代码使用浏览器当前可访问地址生成绝对 URL，不硬编码回环地址或服务端内部端口，示意如下：

```html
<iframe
  src="http://大屏服务地址/screens/大屏ID/embed"
  title="大屏名称"
  style="width: 100%; height: 100%; border: 0"
  allowfullscreen
></iframe>
```

实际生成时转义名称和属性值。集成说明提示父容器应有明确高度，嵌入地址须能被访问者浏览器访问；父站已有 HTTPS 时提供相应可加载的服务入口。此处不增加代理、证书管理或父子页面控制协议。

发布服务对大屏展示及嵌入 HTML 响应允许任意父站点加载，移除相应的 `frame-ancestors 'none'` 限制，并检查没有冲突的 `X-Frame-Options`。嵌入页面内的 API 和 WebSocket 继续连接大屏服务自身地址。开发与生产分别验证，不以 Vite 开发时能打开代替发布结果。

## 7. 验证与验收标准

### 7.1 管理与持久化

1. 创建 A、B 两份大屏，分别配置组件及默认目标/来源；刷新及重启服务后各自内容正确。
2. 重命名 A 后原编辑、展示、嵌入 URL 均继续访问 A；复制得到独立大屏和实例 ID，修改副本不会修改原大屏配置，共享模板关系符合第 3.2 节。
3. 删除普通大屏和 `screen_main` 后，刷新、重启都不复活；删除最后一份后管理页正常，新建第一份仍可用。
4. 旧窗口保存、重命名和删除的并发冲突均有明确反馈，不覆盖新版本、不复活已删除资源。
5. 原有编辑草稿保护、旧 hash/查询入口、明确无效 ID 的错误行为通过回归；旧数据目录不重复单位换算。

### 7.2 iframe 专项用例

持久化一个轻量测试宿主脚本及一份用例说明，不引入 UI/E2E 框架。脚本在独立端口提供宿主页，接受大屏服务地址与 A、B 的 ID 参数，生成两个大屏 iframe，并可增加同 ID 对照框和无效 ID 框。HTML 由测试脚本响应，不创建第二份交互原型文件。

| 用例 | 操作与通过标准 |
| --- | --- |
| 跨来源加载 | 宿主与大屏服务使用不同端口，确认 origin 不同；真实浏览器进入两个 frame，能看到各自保存的实际卡片和数据，没有嵌入拦截。 |
| 实时更新 | 推送可辨识的目标数值，观察 iframe 内对应数值更新；不能仅凭页面壳或 HTTP 200 判断通过。 |
| 切换目标和来源 | 在 A 中切换目标及两种具有不同值的来源，显示正确值；缺失来源明确缺失。B 的指派和显示不受影响。 |
| 同 ID 隔离 | 两个 frame 打开 A，只切换其中一个；另一个保持原选择。刷新被切换的 frame 后恢复保存的默认值，API 回读确认大屏配置未修改。 |
| 嵌入操作边界 | 目标/来源入口可用；标题双击、Ctrl+S、Esc 不触发配置编辑、保存或跳回编辑器，刷新不出现临时切换引起的未保存提示。 |
| 容器适配 | 改变宿主容器宽高，画布随 frame 尺寸适配；允许全屏时验证全屏进入及退出。 |
| 错误资源 | 无效或已删除 ID 在对应 iframe 中显示错误，不展示默认大屏；其他 frame 继续工作。 |
| 发布回归 | 开发服务与构建后的正式静态服务各执行跨来源加载、实时更新和来源切换；正式服务刷新深层嵌入 URL 仍正确加载。 |

实际浏览器验证进入 frame 检查内容和交互，不以 `iframe.onload` 触发作为成功断言，也不让父页面直接跨来源读取子页面 DOM。记录使用的服务地址、不同 origin、测试数据、结果及必要截图；未实测的项明确标注未验证。

测试数据使用 `../liteCodeTool_datas/` 下独立任务目录，测试输出和截图放 `../liteCodeTool_tmp/`；测试脚本只结束本次启动的宿主进程，不改写用户现有大屏。

### 7.3 工程检查

- 检查改动文件格式，运行类型检查、相关纯函数单测及生产构建。
- 对新增删除、空集合启动和响应头做针对性的 HTTP 验证；真实浏览器完成上表专项验收。
- 对既有监控目标/来源及折线高度度量做受影响行为回归，不扩大为通用 UI 自动化体系。

## 8. 实施顺序与闭环

1. 已完成方案定向审查并按推荐范围获得实施授权。
2. 实施获授权后，先在唯一原型内明确管理与嵌入交互，再补齐资源删除、默认资源和空集合。
3. 完成管理页面、稳定地址与草稿协调，然后接入嵌入交互和响应头。
4. 添加并执行 iframe 用例，完成相应回归及文档更新。
5. 验收通过后将本方案移至 `archive/docs/方案/`，在头部写入完成日期和实际验证结论，并修正归档后的相对链接。
6. 实施成果报告同步物理落盘到 `../liteCodeTool_tmp/walkthrough.md`。提交和推送仅在用户另行要求时执行。

实施与实际验证结果另记于成果报告；未完成验收前不宣称全部通过。
