## 2. 当前实现与问题定位

1. `vite.config.ts` 和 `server/index.mjs` 默认绑定 `127.0.0.1`；`tools/launcher.mjs` 还会向发布服务强制传入该地址。只修改其中一个入口无法覆盖开发和发布。
2. 后端 `allowedOrigin()` 同时校验 Host 白名单和 Origin，HTTP 与 WebSocket 都会调用。真实数据接入还要求 `INGEST_TOKEN`；发布启动器自动生成并检查 `connection.json` 中的凭据。
3. `Inspector.vue` 中的英文标题是固定文案。`WorkspaceToolbar.vue` 的两侧按钮有无障碍标签，但没有相应的悬浮文字提示。
4. `CardHeaderProperties.vue` 把未设置的副标题显示为空；`core.ts` 与 `InstanceCard.vue` 仍有按槽位生成默认文字的逻辑，因此表单和卡片表现不一致。
5. `TemplateProperties.vue` 对超出尺寸范围的输入直接返回，未提示，也未将原生输入框中的无效值写回。
6. `LightProperties.vue` 与 `ControlRenderer.vue` 都使用同一份 `colorRules`。数据源模式切换没有区分固定颜色和动态规则，固定模式也暴露了增删规则界面。

## 3. 技术路径

### 3.1 局域网默认可访问

- Vite 和后端默认监听 `0.0.0.0`，发布启动器不再强制仅监听回环地址。已有显式监听地址配置能力可保留，但默认启动无需填写白名单或凭据。
- Vite 接受局域网 IP 与主机名访问，不设置主机白名单。开发环境继续通过 `/api`、`/ws` 代理连接本机后端；代理的上游地址保留回环地址即可，不应把浏览器请求硬编码为 `127.0.0.1`。
- 删除后端 Host、Origin 白名单拦截，以及 `ALLOWED_HOSTS`、`DEV_ORIGIN` 对访问权限的控制；WebSocket 保留正确的 `/ws` 路由和握手处理。
- 后端为跨端口或跨来源的直接 API 调用提供开放的 CORS 响应与 OPTIONS 预检。允许 API 所需请求方法与请求头，暴露 `ETag`；成功与错误响应都需包含一致的跨来源响应头。当前不采用 Cookie 身份认证，不增加凭据式跨来源流程。
- 真实模式 `/api/ingest` 取消 Bearer Token 校验；合法数据无需凭据即可提交。删除启动器自动生成、读取、检查接入凭据的流程，已有外部 `connection.json` 不再影响启动，也不自动删除或重写该文件。
- 保留已有数据模式、JSON、字段类型、尺寸及保存版本检查，以及演示／真实数据模式的职责区别。这些用于保证数据和功能正确，不新增登录、权限、IP 段判断或限流体系。
- 启动输出同时给出本机访问地址与可用局域网 IPv4 地址；存在多个网卡时可列出多个地址供使用，不把 `0.0.0.0` 当作用户访问链接。健康检查和本机自动打开浏览器仍使用回环地址。
- 同步真实数据接入示例，去掉必须配置 Token 的步骤。前端 API 与实时连接继续基于当前页面地址，确保另一台电脑不会误连自己的本机服务。

### 3.2 组件工坊页面提示

- 两侧按钮根据面板当前状态设置 `title` 为“收起”或“展开”，使用现有浏览器悬浮提示即可；无障碍标签包含目标面板名称并与动作同步。
- 删除属性检查器标题右侧英文装饰，不改变中文标题和面板布局。
- 两处属于共用界面组件，组件工坊和大屏编辑态保持一致，不复制页面实现。

### 3.3 副标题只显示明确配置的文字

- 统一副标题解析入口，移除 `core.ts`、卡片渲染以及表单占位提示中的自动补字逻辑。
- 模板副标题未设置或为空，均显示为空；新建模板默认留空。旧模板中明确保存的“目标监控”“数据总览”也属于用户已有文字，原样保留。
- 保留实例对模板的继承语义：实例未配置副标题时继承模板；实例显式设为空字符串时隐藏；实例有文字时显示自己的文字。
- 输入框显示实际生效的副标题，不能再出现输入框为空但卡片显示继承文字的情况。清空通过输入框提交为空字符串，从而明确隐藏。
- 工坊取消“恢复默认副标题”按钮；实例端改为“恢复模板副标题”，移除实例覆盖后重新继承模板，模板没有文字时仍为空。
- 隐藏副标题后不保留文字占位。检查器、卡片就地编辑、工坊预览、编辑态、显示态共用上述语义。

### 3.4 模板尺寸修正与反馈

- 抽取或复用一个轻量的尺寸规范化纯函数，前端提交时使用现有宽高上下限；输入框声明对应 `min`、`max`。
- 输入过程中允许暂时为空或未完成数字，不在每次键入时改写。失焦或回车统一提交，避免事件重复导致同一提示出现两次。
- 有限数值超出范围时夹取到最近边界，例如宽 50 修正为 80、高 3000 修正为 2160；提示“宽度最小为 80，已调整为 80”等具体原因。
- 空输入或无法转换为有限数值时恢复上一次有效值，提示填写有效尺寸；不能让 `Number('')` 被当作用户输入 0。
- 无论结果是否与原数据相同，都将最终值写回输入框，覆盖“连续输入越界值但响应式数据未变化”的情况。
- 只有有效尺寸实际变化时，才更新模板布局并调用现有 `fitGeometry` 约束内部控件。保持现有控件边界策略，不额外引入整体同比缩放。
- 服务端继续校验持久化尺寸范围；界面自动修正不能代替保存接口的数据检查。

### 3.5 指示灯两种模式独立保存

采用最小兼容改动，不为固定模式新增规则数组：

| 字段 | 用途 |
| --- | --- |
| `props.sourceMode` | 当前使用固定内容还是动态绑定。 |
| `props.staticValue` | 固定状态文字，复用已有字段。 |
| `props.staticColor` | 新增的固定状态颜色，使用六位十六进制颜色格式。 |
| `props.colorRules` | 保留原字段，专用于动态状态匹配规则。 |
| `binding` | 动态数据绑定，切到固定模式时仍保留。 |

- 固定模式界面只出现一次状态文字输入和一个颜色选择器；不显示匹配值列表、添加或删除规则按钮。固定灯色直接读取固定颜色，不再拿固定文字去匹配动态规则。
- 动态模式显示已有绑定选项与多条状态颜色规则。缺值继续显示“状态未知”，未匹配状态使用现有中性色，不推断正常。
- 新固定指示灯采用明确的初始状态文字与现有中性色；复用现有固定内容默认值，不凭空赋予“正常”含义。空状态文字继续遵守现有空值显示规则，不自动补“正常”。
- 切换模式只切换使用哪份配置，首次切入动态时仍可按现有逻辑初始化缺失的绑定；已保存的另一模式内容保持不变。
- 模板保存、重新打开、实例私有覆盖、撤销／重做及恢复模板默认值均需覆盖新颜色字段。

#### 旧配置兼容

1. 保留旧 `colorRules` 的全部动态规则，不删除、不截断为一条。
2. 缺少 `staticColor` 时，按旧逻辑用固定值严格匹配旧规则，取第一个命中颜色；未命中时取原中性色 `#7995B1`，从而保留原固定模式的显示颜色。
3. 检查器与渲染器共用兼容解析，不分别实现。缺少 `sourceMode` 的旧数据沿用既有规则：存在绑定则为动态，否则为固定。
4. 在第一次修改固定文字、修改动态规则或切换模式前，将兼容解析得到的固定颜色写入当前编辑对象，避免后续改动让固定颜色再次跟随动态规则变化。
5. 实例兼容解析先考虑模板配置与实例覆盖的实际生效结果，再写入实例私有覆盖；只编辑实例时不得回写源模板。
6. 加载旧文件时不进行批量磁盘迁移；用户编辑并保存时按现有保存流程持久化新字段。复制、导入和导出需保留新字段。
7. 在共享校验逻辑中接受并验证可选 `staticColor`，旧配置缺少该字段仍有效；实例覆盖与模板采用一致的颜色格式要求。
