## 问题陈述 (Problem Statement)

第三方开发者根据项目基线（`8dd3a9f`）完成了 v0.2.0 版纯图表科技蓝低代码大屏平台的工程化研发，交付了包含完整前后端源码的本地运行包（`LiteCodeTool_v0.2.0_可运行软件包_含源码.zip`）及《方案差距对照表》。然而当前项目面临以下断层与缺口：
1. **源码未合入主干**：完整的前后端工程源码孤立存在于 zip 压缩包中，Git 仓库主干尚未承载源码，无法直接执行持续迭代与版本追踪；
2. **全局统计时序断层 (F1)**：时序折线图（LineChart）仅支持绑定具体船舶实体槽位（如海巡01的航速走势），无法直接绑定全港统计指标（如“在港船舶总数”），导致大盘宏观时序与微观单船时序能力不拉齐；
3. **表格数据新鲜度未统一 (F3)**：单值卡片具备超时置灰与陈旧标记能力，但表格控件直接格式化数据，某船长时间停止推流时仍以鲜绿高光显示“在航”，缺少可配置、可关闭的数据陈旧（Stale）视觉警示；
4. **工程构建与平台验证未闭环**：当前交付包仅验证了 Linux 下自包含离线编译，尚未在 Windows 目标机上完成标准 `npm install`、`vite build`、`vue-tsc` 类型检查以及 Windows 原生命令行一键启动闭环。

---

## 解决方案 (Solution)

针对上述问题，本方案提供一套系统性的源码合并与差距补齐落地路径：
1. **平铺合并入库**：将 `source/liteCodeTool/` 全量源码平铺合入仓库根目录，形成包含现代前端 Vue 3 + TypeScript 与 Node.js 外部数据隔离服务的单一应用工程；
2. **补齐全局时序曲线 (F1)**：扩展 `Series` 数据契约支持 `target: 'global'`，曲线组件同时兼容实体槽位时序与全港非实体指标时序；
3. **补齐可配置表格陈旧提示 (F3)**：在表格控件中引入基于数据源时间戳的动态陈旧判定，支持在属性检查器中自定义超时秒数（`tableStaleSeconds`），并支持设为 0 或关闭开关以停用；
4. **统一双轨构建与原生启动**：保留 2 秒极速自包含离线编译机制，同时补齐标准 Vite 构建与 Windows 原生 `.cmd` 一键启动链路，达成全链路验收闭环。

## 用户故事 (User Stories)

1. 作为一名调度系统设计人员，我想要将交付的代码包平铺合并进 Git 仓库根目录，以便于在统一的标准工程中持续演进代码并由版本控制严格受控。
2. 作为一名大屏监控运维人员，我想要在时序曲线控件中直接添加“全港船舶总数”等宏观统计指标，以便于实时观察全港宏观通航密度的时序变化走势。
3. 作为一名大屏监控运维人员，我想要在某艘船舶长时间未上报 AIS 增量时，表格中的对应行自动呈现陈旧弱化提示（如置灰或标记已停更），以便于一眼辨识出停更数据，防止将陈旧历史误判为实时动态。
4. 作为一名低代码大屏配置人员，我想要在表格属性面板中自由设置数据过期的超时秒数，甚至在展示普通静态名册时将其完全关闭，以便于根据不同的业务时效场景灵活配置。
5. 作为一名大屏现场操作人员，我想要在显示态通过 456px 侧滑抽屉快速输入船名或 MMSI 模糊查找目标船舶并一键换船，以便于在全港数百艘船只中秒级定位目标并调度大屏卡片。
6. 作为一名现场技术部署人员，我想要在断网环境下通过离线命令快速编译应用，也能在联网开发环境下执行标准 `npm run build:vite` 与 `vue-tsc` 检查，以便于兼顾工程严谨性与现场交付容灾。
7. 作为一名 Windows 终端用户，我想要双击 `启动演示.cmd` 或 `启动真实模式.cmd` 即可一键拉起后端服务并在浏览器中直接打开大屏，以便于零配置、开箱即用地运行整个系统。

## 实现决策 (Implementation Decisions)

### 决策 1：源码平铺式合库架构 (ADR 0007)
将 `source/liteCodeTool/` 平铺至代码仓库根目录，形成极简实用的单一应用工程结构：
- `package.json`、`tsconfig.json`、`vite.config.ts` 位于根目录；
- 前端源码归入 `src/`（包含 `engine/core.ts` 核心算法、`engine/runtime.ts` 状态机、Vue 3 组件及样式）；
- 后端服务归入 `server/`（包含 `index.mjs`、`dev.mjs`、`defaults.mjs`）；
- 离线构建与自包含依赖归入 `tools/` 与 `vendor/`；
- 原有文档体系（`docs/`、`CONTEXT.md`、`AGENTS.md`）保持同级受控，不被代码冲刷。

### 决策 2：时序曲线扩展全局序列契约 (F1 · ADR 0006)
在 `src/types.ts` 中扩展 `Series` 接口，使单条曲线支持两种取数模式：

```typescript
// 原型内联核心契约 (来自 types.ts 扩展)
export interface Series {
  target?: 'slot' | 'global'; // 缺省或 'slot' 为实体槽位；'global' 为全局模式指标
  slotId?: string;            // 当 target === 'slot' 时必填
  schemaType?: string;        // 当 target === 'global' 时必填，如 'port_stats'
  field: string;              // 数值字段标识，如 'speed' 或 'total_vessels'
  color?: string;             // 曲线颜色
  label?: string;             // 自定义标签（缺省时自动读取 Schema 字段名）
}
```

- **数据提取逻辑 (`src/components/LineChart.vue`)**：若 `s.target === 'global'`，从 `state.store.get(s.schemaType, '_global')` 取得历史滑动窗口数据，图例自动呈现全局字段名；
- **校验逻辑 (`src/engine/core.ts`)**：放宽原仅允许 slotId 的硬限制，允许绑定合法全局 Schema 的数值型字段。

### 决策 3：表格支持可配置时间门槛的数据陈旧提示 (F3 · ADR 0008)
在 `src/types.ts` 的 `ControlProps` 中增加表格过期配置：

```typescript
// 原型内联核心契约 (来自 types.ts 扩展)
export interface ControlProps {
  // ... 既有控件属性 ...
  tableStaleEnabled?: boolean;  // 表格数据陈旧提示开关，默认 true
  tableStaleSeconds?: number;   // 判定陈旧的超时门槛（秒），默认 120 秒；<=0 表示不启用
}
```

- **动态判定 (`src/components/ControlRenderer.vue`)**：从行记录字段中取得最新源时间戳 `max(timestamps)`，若 `now - maxTimestamp > tableStaleSeconds * 1000` 且启用开关，则为该行追加 `.row-stale` 样式；
- **属性联动 (`src/components/Inspector.vue`)**：检查器提供开关与输入框，允许用户自由设定秒数或关闭。

### 决策 4：交互体验收敛为“全局抽屉 + 局部快捷切换”
正式确认 Q5 裁决：以 456px 侧滑“监控对象抽屉”（支持船名/MMSI实时模糊搜索与集中调度固化）作为大范围检索真源；卡片局部保留下拉快速切船与微型气泡。不在紧凑卡片角落重复增加微型搜索输入框。

### 决策 5：离线与标准双轨构建 (Dual-Build)
- 轨一（离线极速）：`npm run build`（调用 `node tools/build.mjs`），脱机自包含编译，2 秒完成；
- 轨二（标准工程）：`npm run build:vite`（调用 `vue-tsc --noEmit && vite build`），提供全量类型安全检查与生产级 Tree-shaking 打包。

## 测试决策 (Testing Decisions)

### 1. 测试切面 (Test Seams)
本项目优先复用既有高层测试切面，聚焦两个关键 Seam：
- **Seam A (核心纯函数计算切面 · `src/engine/core.ts`)**：作为数据解析、实体池聚合、时效计算与配置验证的统一测试切面，所有单测均通过公开函数接口进行，不依赖 DOM 或浏览器环境；
- **Seam B (HTTP / WS 服务端端到端切面 · `server/index.mjs`)**：测试真实网络增量推流、原子文件写入与多实例快照回读。

### 2. 良好测试标准
- 只测试外部行为契约（输入 Schema、输出 ResolvedValue、验证抛错），严禁测试内部私有变量；
- 严格遵循极简实用主义，单测执行时间控制在秒级（< 500ms），绝不引入重型 UI / E2E 浏览器驱动框架。

### 3. 测试用例补充矩阵
既有 22 项单测全部保持通过，并追加以下关键测试用例：
1. `test('全局统计时序曲线提取与滑动窗口裁剪正常')`：验证 `target: 'global'` 时从全局实体池正确获取历史点并留白；
2. `test('全局统计曲线配置校验通过')`：验证 `validateTemplate` 与 `validateScreen` 对合法全局指标不报错；
3. `test('表格单行数据陈旧判定符合配置时间')`：向实体注入超期时间戳，验证开启时返回 stale=true，设为 0 或关闭时返回 stale=false。

## 范围外说明 (Out of Scope)

以下内容明确不包含在本次实施范围之内：
1. **复杂 SQL 式查询语言与多图联动筛选**：首期表格仅支持单字段等值过滤，不引入复杂 AND/OR 嵌套查询条件或图表间点击动态反选；
2. **真实 AIS / NMEA 硬件报文解析**：平台仅提供标准 JSON 契约通信接口，不包含专用串口雷达驱动或特定硬件解析库；
3. **用户认证与多租户权限系统**：系统专注于工业大屏单机/局域网私有化轻量部署，不包含多租户审批流与数据库鉴权；
4. **重型 E2E / UI 自动化测试体系**：坚决贯彻轻量实用红线，不引入 Playwright / Cypress 等大型端到端测试。
