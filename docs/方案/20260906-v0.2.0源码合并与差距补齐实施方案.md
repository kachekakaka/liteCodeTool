## 问题陈述 (Problem Statement)

第三方开发者根据项目基线完成了 LiteCodeTool v0.2.0 版工程化研发并交付源码包，经本地隔离核验，核心算法 22/22 单元测试全绿、离线编译顺畅。但在方案 V1.0 及 V2.0 进阶复核中，严格核查发现了以下关键断层与运行期隐患：

1. **全局曲线界面配置盲区 (R1 / F1)**：原包 `src/components/Inspector.vue` 硬编码了“添加曲线必须依赖槽位”，未在属性检查器中暴露全局指标选择，导致用户无法在设计器界面制作零槽位的宏观时序曲线模板；
2. **时效判定粒度与断流反例 (R2 / F3)**：仅用整行最新时间判定会导致“某列停更 5 分钟、另一列刚更新时整行仍显新鲜”的反例，且计算未由时钟常态驱动，完全断流时无法自然变灰；无时间戳时不能错误标注为“实时正常”；
3. **`start:vite` 启动命令缺参数报错 (Node 22 运行报错)**：源码 `server/index.mjs` 中直接导入了 `core.ts`，在 Node 22.16 原生环境下未传 `--experimental-strip-types` 执行会直接抛出 `ERR_UNKNOWN_FILE_EXTENSION` 退出码 1；且此前命令无法直接独立启动 Vite 产物进行有效性验证；
4. **启动器路径错位与数据目录漂移隐患**：原发行包的 `.cmd` 启动脚本是为打包后的目录结构设计的，平铺到根目录会找不到入口；且离线构建产物运行在临时目录时，若未显式指定数据目录，会错误将持久化数据写入 `liteCodeTool_tmp/`，面临被清理丢失的严重风险；
5. **合库文件清单笔误**：原方案将单文件样式误写为目录 `src/styles/`（实际为 `src/styles.css`），且漏列了前端入口 `index.html`。

## 解决方案 (Solution)

全面吸收审核与复核意见，坚持极简实用与红线隔离原则，落实五大技术实施方案：

1. **平铺合库受控推进 (ADR 0007)**：纠正 `src/styles.css` 与补齐 `index.html`，按严格白名单平铺合并 `source/liteCodeTool/` 入仓库根目录，人工逐节合并文档，保留既有受控文档体系；
2. **全局曲线全链路补齐 (R1 / F1 · ADR 0006)**：改造 `Inspector.vue` 支持来源单选（“监控对象” vs “全局指标”），全局模式免槽位声明并自动列出非实体数值字段；`LineChart.vue` 与 `core.ts` 贯通数据提取、校验与持久化；
3. **表格双层时效与时钟驱动 (R2 / F3 · ADR 0008)**：下沉纯函数至 `core.ts`，由系统时钟驱动；实现“整行弱化置灰 + 时间列停更标注”，属性面板支持 `staleEnabled` 开关与 `staleSeconds`（10~3600s，设为 0 关闭）；无时间戳显示未知，关闭仅表示不监测，绝不伪造“实时正常”；
4. **双轨构建修复与数据目录安全锁 (ADR 0007)**：
   - 修复 `start:vite` 补充 `--experimental-strip-types` 参数；
   - 无论何种构建与启动轨道，服务端启动命令均**显式传入绝对计算的 `DATA_DIR`**（死死锁定在仓库上一级的 `../liteCodeTool_datas/`），绝不让大屏配置误落入临时目录；
   - 区分“仓库开发态命令”与“绿色发行包构建（`tools/build.mjs` 统一输出自包含包）”；
5. **诚实界定功能边界 (R5)**：建立本次实现与显式延期对照表，不模糊 F2 集合与 F3 字段级质量的审计边界。

## 用户故事 (User Stories)

1. 作为一名大屏设计人员，我想要在组件工坊制作曲线模板时，直接在属性检查器中选择“全局数据指标”并绑定全港船舶总数，无需声明假槽位，以便于零门槛制作宏观大盘时序图。
2. 作为一名大屏设计人员，我想要在时序曲线配置中自由切换数据来源并保留独立颜色与标签，以便于灵活编排多指标时序对比。
3. 作为一名大屏监控调度员，我想要在某艘船舶停止上报 AIS 时，表格中对应行自动呈现弱化置灰且时间列显式标注停更，以便于一眼辨别停更船只，防止把历史误当实时。
4. 作为一名低代码配置人员，我想要在表格属性面板中自定义数据超时的判定秒数，或在普通静态表格上一键关闭超时检测，以便于适应不同时效要求的业务数据。
5. 作为一名现场操作人员，我想要在显示态通过 456px 侧滑抽屉集中搜索调度目标船只，同时在卡片局部保留快捷换船气泡，以便于兼顾全局大范围检索与局部高频微调。
6. 作为一名现场技术部署人员，我想要在断网环境下通过离线命令极速构建应用，也能在开发机上执行完整的 `npm run build:vite` 与修复后的 `npm run start:vite` 独立验证 Vite 编译产物，以便于确保两轨各自 100% 可用且互不干扰。
7. 作为一名系统使用者，我想要不管通过何种方式启动程序，我保存的大屏配置和船舶槽位都能稳稳存放在专门的数据目录中，绝不随临时目录清理而丢失。

### 决策 2：全局曲线全链路契约与检查器改造 (R1 / F1 · ADR 0006)

#### 数据契约 (`src/types.ts`)
```typescript
export interface Series {
  target?: 'slot' | 'global'; // 缺省为 'slot' 兼容存量；'global' 为全局模式指标
  slotId?: string;            // target==='slot' 时必填
  schemaType?: string;        // target==='global' 时必填（对应 isEntity===false 的模式）
  field: string;              // 数值字段名，如 'total_vessels'
  color?: string;             // 曲线色值
  label?: string;             // 自定义标签（缺省时自动使用 Schema 字段名）
}
```

#### 检查器交互改造 (`src/components/Inspector.vue`)
- **零槽位支持**：在曲线表单中，添加系列时提供单选：`● 监控对象槽位` vs `● 全局统计指标`；若选择全局指标，**完全不要求模板声明对象槽位**；
- **Schema 动态枚举**：全局模式仅列出 `isEntity === false` 的 Schema（如 `port_stats`）及其全部数值型字段；
- **互斥清理**：切换来源时，自动清理旧来源的残留键（选全局时清空 `slotId`，选槽位时清空 `schemaType`）；
- **校验放宽 (`src/engine/core.ts`)**：`validateTemplate` 与 `validateScreen` 校验 Series 时，允许 `target === 'global'` 绑定合法的全局数值字段。

### 决策 3：表格可配置双层时效与时钟常态驱动 (R2 / F3 · ADR 0008)

#### 统一命名与配置规范 (`src/types.ts`)
统一使用 `staleEnabled` 与 `staleSeconds`，杜绝命名分裂：

```typescript
export interface ControlProps {
  // ... 既有属性 ...
  staleEnabled?: boolean;     // 时效提示总开关，默认 true
  staleSeconds?: number;      // 超时门槛（秒），默认 120；<=0 表示不启用
}
```

#### 纯函数下沉与语义说明 (`src/engine/core.ts`)
将陈旧判定提取为独立公开纯函数，供 Vue 组件与测试用例共用：

```typescript
export function isRecordStale(record: EntityRecord, staleSeconds: number, now: number): boolean {
  if (staleSeconds <= 0) return false;
  const timestamps = Object.values(record.timestamps ?? {});
  if (!timestamps.length) return false; // 无时间戳表示时效未知，不视为陈旧，界面展示 --
  const latest = Math.max(...timestamps);
  return (now - latest) > (staleSeconds * 1000);
}
```

- **语义严肃性**：
  - 无时间戳或字段缺失时，界面呈现 `--` 或“时间未知”，严禁标记为“实时正常”；
  - 关闭时效开关仅表示“不进行陈旧检测”，保持原始数据展示，绝不伪装为“实时正常”。
- **双层视觉呈现 (`src/components/ControlRenderer.vue`)**：
  - 行级：若 `isRecordStale(...)` 为 true，为 `<tr>` 追加 `.row-stale` 样式（背景微弱变暗，文字与状态徽标适度置灰降低刺眼感）；
  - 时间列：在“最后上报时间”单元格直接呈现时间置灰或显示 `(停更)` 标识；
  - 时钟常态驱动：严格依赖响应式 `state.now`（每秒递增定时器），断流停更也能自动变灰。

### 决策 4：双轨构建独立命令与启动参数修复 (R3 · ADR 0007)

在 `package.json` 中明确分离双轨产物与启动命令，**修复 Node 22+ 运行参数并锁死外部数据目录**：

```json
{
  "scripts": {
    "dev": "node --experimental-strip-types server/dev.mjs",
    "dev:demo": "node --experimental-strip-types server/dev.mjs --demo",
    "test": "node --experimental-strip-types --test tests/core.test.ts",
    "build": "node tools/build.mjs",
    "start": "node --experimental-strip-types -e \"process.env.DATA_DIR=process.env.DATA_DIR||require('node:path').resolve('../liteCodeTool_datas'); import('../liteCodeTool_tmp/release/app/server/index.mjs')\"",
    "build:vite": "vue-tsc --noEmit && vite build",
    "start:vite": "node --experimental-strip-types -e \"process.env.CLIENT_DIR='../liteCodeTool_tmp/dist'; process.env.DATA_DIR=process.env.DATA_DIR||require('node:path').resolve('../liteCodeTool_datas'); import('./server/index.mjs')\""
  }
}
```

- **修复说明**：补充 `--experimental-strip-types` 参数彻底杜绝 Node 22 执行 `import core.ts` 时的语法报错；显式注入 `CLIENT_DIR` 与 `DATA_DIR`，确保 Vite 产物与持久数据目录 100% 独立锚定。

## 范围外说明 (Out of Scope)

1. **高级动态集合引擎**：不引入复杂 SQL 查询、AND/OR 逻辑表达式编辑器或表格反选联动；
2. **逐单元格独立时效染色**：表格不进行逐格差异化染色，避免界面视觉斑驳；
3. **真实硬件报文与驱动**：仅提供带 Token 的标准 JSON HTTP/WS 接口，不含专用 AIS/NMEA 硬件串口解析；
4. **重型 E2E 自动化测试框架**：遵守 `AGENTS.md` 红线，不引入 Playwright / Cypress，仅用轻量脚本与浏览器无头验证。
