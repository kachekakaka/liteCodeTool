## 问题陈述 (Problem Statement)

第三方开发者根据项目基线完成了 LiteCodeTool v0.2.0 版工程化研发并交付源码包，经本地隔离核验，核心算法 22/22 单元测试全绿、离线编译顺畅。但经对方案 V1.0 及代码的严格审核（详见 `liteCodeTool_合并方案审核意见_8a957d9.md`），发现若直接实施仍面临以下关键断层与工程风险：

1. **全局曲线界面配置盲区 (R1 / F1)**：原包 `src/components/Inspector.vue` 硬编码了“曲线必须声明槽位”，未在属性检查器中暴露全局指标选择，导致用户无法在设计器界面制作零槽位的宏观时序曲线模板；
2. **时效判定粒度与断流反例 (R2 / F3)**：仅用整行最新时间判定会导致“某列停更 5 分钟、另一列刚更新时整行仍显新鲜”的反例，且计算未由时钟常态驱动，完全断流时无法自然变灰；
3. **双轨构建启动混淆 (R3)**：`package.json` 的 `start/demo` 命令硬编码指向离线构建输出目录，执行 `npm run build:vite` 后无法直接独立启动 Vite 产物进行有效性验证；
4. **合库路径与边界模糊 (R4~R6)**：原方案将 `src/runtime.ts` 误写为 `src/engine/runtime.ts`；对 F2 动态集合与 F3 逐字段质量的完成边界缺乏诚实、严密的界定。

---

## 解决方案 (Solution)

全面吸收审核意见，以“平铺合库、保留现有成果、补齐界面闭环、诚实界定边界、双轨独立验证”为原则，系统性落实五大技术方案：

1. **平铺合库受控推进 (ADR 0007)**：修正源码路径（`src/runtime.ts`），按严格白名单平铺合并 `source/liteCodeTool/` 入仓库根目录，人工逐节合并文档，保留既有受控文档体系；
2. **全局曲线全链路补齐 (R1 / F1)**：改造 `Inspector.vue` 支持来源单选（“监控对象” vs “全局指标”），全局模式免槽位声明并自动列出非实体数值字段；`LineChart.vue` 与 `core.ts` 贯通数据提取、校验与持久化；
3. **表格双层时效与时钟驱动 (R2 / F3 · ADR 0008)**：下沉纯函数至 `core.ts`，由系统时钟驱动；实现“整行弱化置灰 + 时间列停更标注”，属性面板支持 `staleEnabled` 开关与 `staleSeconds`（10~3600s，设为 0 关闭）；
4. **双轨独立构建与启动 (R3)**：明确离线轨（`npm run build` -> `npm run start`）与标准 Vite 轨（`npm run build:vite` -> `npm run start:vite`，通过 `CLIENT_DIR` 显式指定目录），分别进行 Windows 原生启动验收；
5. **诚实界定功能边界 (R5)**：建立本次实现与显式延期对照表，不模糊 F2 集合与 F3 字段级质量的审计边界。

## 用户故事 (User Stories)

1. 作为一名大屏设计人员，我想要在组件工坊制作曲线模板时，直接在属性检查器中选择“全局数据指标”并绑定全港船舶总数，无需声明假槽位，以便于零门槛制作宏观大盘时序图。
2. 作为一名大屏设计人员，我想要在时序曲线配置中自由切换数据来源并保留独立颜色与标签，以便于灵活编排多指标时序对比。
3. 作为一名大屏监控调度员，我想要在某艘船舶停止上报 AIS 时，表格中对应行自动呈现弱化置灰且时间列显式标注停更，以便于一眼辨别停更船只，防止把历史误当实时。
4. 作为一名低代码配置人员，我想要在表格属性面板中自定义数据超时的判定秒数，或在普通静态表格上一键关闭超时检测，以便于适应不同时效要求的业务数据。
5. 作为一名现场操作人员，我想要在显示态通过 456px 侧滑抽屉集中搜索调度目标船只，同时在卡片局部保留快捷换船气泡，以便于兼顾全局大范围检索与局部高频微调。
6. 作为一名现场技术部署人员，我想要在断网环境下通过离线命令极速构建应用，也能在开发机上执行完整的 `npm run build:vite` 与 `npm run start:vite` 独立验证 Vite 编译产物，以便于确保两轨各自 100% 可用且互不干扰。
7. 作为一名 Windows 终端用户，我想要运行根目录原生 `.cmd` 脚本即可一键拉起后端服务并直接在浏览器中打开大屏，以便于零环境配置即可运行验证。

### 决策 2：全局曲线全链路契约与检查器改造 (R1 / F1 · ADR 0006)

#### 数据契约 (`src/types.ts`)
```typescript
export interface Series {
  target?: 'slot' | 'global'; // 缺省为 'slot' 兼容存量；'global' 为全局模式指标
  slotId?: string;            // target==='slot' 时必填
  schemaType?: string;        // target==='global' 时必填（对应 isEntity===false 的模式）
  field: string;              // 数值字段名，如 'total_vessels'
  color?: string;             // 曲线色值
  label?: string;             // 自定义标签（缺省时自动使用 Schema 字段名）
}
```

#### 检查器交互改造 (`src/components/Inspector.vue`)
- **零槽位支持**：在曲线表单中，添加系列时提供单选：`● 监控对象槽位` vs `● 全局统计指标`；若选择全局指标，**完全不要求模板声明对象槽位**；
- **Schema 动态枚举**：全局模式仅列出 `isEntity === false` 的 Schema（如 `port_stats`）及其全部数值型字段；
- **互斥清理**：切换来源时，自动清理旧来源的残留键（选全局时清空 `slotId`，选槽位时清空 `schemaType`）；
- **校验放宽 (`src/engine/core.ts`)**：`validateTemplate` 与 `validateScreen` 校验 Series 时，允许 `target === 'global'` 绑定合法的全局数值字段。

### 决策 3：表格可配置双层时效与时钟常态驱动 (R2 / F3 · ADR 0008)

#### 统一命名与配置规范 (`src/types.ts`)
统一使用 `staleEnabled` 与 `staleSeconds`，杜绝命名分裂：

```typescript
export interface ControlProps {
  // ... 既有属性 ...
  staleEnabled?: boolean;     // 时效提示总开关，默认 true
  staleSeconds?: number;      // 超时门槛（秒），默认 120；<=0 表示不启用
}
```

#### 纯函数下沉 (`src/engine/core.ts`)
将陈旧判定提取为独立公开纯函数，供 Vue 组件与测试用例共用：

```typescript
export function isRecordStale(record: EntityRecord, staleSeconds: number, now: number): boolean {
  if (staleSeconds <= 0) return false;
  const timestamps = Object.values(record.timestamps ?? {});
  if (!timestamps.length) return false;
  const latest = Math.max(...timestamps);
  return (now - latest) > (staleSeconds * 1000);
}
```

#### 渲染与时钟驱动 (`src/components/ControlRenderer.vue`)
- **双层视觉提示**：
  - 行级：若 `isRecordStale(row.record, effectiveStaleSeconds, state.now)` 成立，为 `<tr>` 追加 `.row-stale` 样式（背景微弱变暗，文字与状态徽标适度置灰降低刺眼感）；
  - 时间列：在“最后上报时间”单元格直接呈现时间置灰或显示 `(停更)` 标识；
- **时钟常态驱动**：计算严格依赖响应式 `state.now`（每秒递增定时器），即便完全断流停更，时间到达后也能自动转为陈旧态；
- **检查器表单**：增加“数据时效警示”开关与“超时秒数”输入框（10~3600 秒，设为 0 关闭）；关闭时恢复原始显示。

### 决策 4：双轨构建独立命令与产物隔离 (R3 · ADR 0007)

在 `package.json` 中明确分离双轨产物与启动命令：

```json
{
  "scripts": {
    "dev": "node --experimental-strip-types server/dev.mjs",
    "test": "node --experimental-strip-types --test tests/core.test.ts",
    "build": "node tools/build.mjs",
    "start": "node ../liteCodeTool_tmp/release/app/server/index.mjs",
    "build:vite": "vue-tsc --noEmit && vite build",
    "start:vite": "node -e \"process.env.CLIENT_DIR='../liteCodeTool_tmp/dist'; import('./server/index.mjs')\""
  }
}
```

- **服务端改造 (`server/index.mjs`)**：优先读取 `process.env.CLIENT_DIR`，使 `start:vite` 能严格挂载 Vite 产物目录；
- **验证要求**：本地验收时分别独立运行 `npm run build && npm run start` 与 `npm run build:vite && npm run start:vite`，逐一访问测试，杜绝伪启动。

## 范围外说明 (Out of Scope)

1. **高级动态集合引擎**：不引入复杂 SQL 查询、AND/OR 逻辑表达式编辑器或表格反选联动；
2. **逐单元格独立时效染色**：表格不进行逐格差异化染色，避免界面视觉斑驳；
3. **真实硬件报文与驱动**：仅提供带 Token 的标准 JSON HTTP/WS 接口，不含专用 AIS/NMEA 硬件串口解析；
4. **重型 E2E 自动化测试框架**：遵守 `AGENTS.md` 红线，不引入 Playwright / Cypress，仅用轻量脚本与浏览器无头验证。
