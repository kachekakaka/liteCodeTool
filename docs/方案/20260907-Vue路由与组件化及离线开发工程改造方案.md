## 2. 现状与影响

- `src/App.vue` 同时承载编辑态、显示态、组件工坊、数据状态页面，以及导航、工具栏、资产库、帮助弹窗、画布缩放、拖拽与快捷键。已有卡片等子组件，但页面级职责仍集中，大量模板和处理函数挤在单行。
- `src/runtime.ts` 集中维护响应式状态、HTTP、WebSocket、历史快照、保存、导入导出、模板编辑和导航；`setView`、`editTemplate`、`hashchange` 分别修改页面状态与地址，缺少统一路由入口。
- `tools/build.mjs` 自行解析 Vue 文件并实现模块加载，限制单文件组件语法，当前仅特殊处理 Vue 依赖。现有 Vite 构建与其并行，重构需要同步收敛。
- `server/index.mjs` 按请求路径读取静态文件，尚无前端 history 路由回退；直接访问新路径目前会找不到文件。
- `server/dev.mjs` 已可同时启动 Vite 和后端，但没有团队共享的 VS Code 启动配置；`.gitignore` 还会忽略整个 `.vscode/`。
- 当前无统一格式化配置。开发手册仍描述双轨构建，且命令表中的 `dev:live` 在 `package.json` 中不存在，需要随实现对齐。

这些结论来自源码检查，不代表已执行运行验证。

### 组件拆分标准

- `App.vue` 不再通过整页 `v-if` 分支切换业务页面，也不直接实现拖拽和模板编辑。
- 画布编辑与显示共享渲染组件，通过明确属性传入编辑能力；页面保留自身工具栏、状态条和快捷键，避免在公共组件内部继续堆叠整页模式判断。
- 属性检查器至少按画布设置、卡头、对象槽位、字段绑定、外观、表格和曲线配置拆分；曲线系列和坐标映射处理跟随相应区域归属，不能把整个检查器搬进另一个巨型文件。
- `ControlRenderer` 保留渲染分发职责；表格、图片、曲线及复杂控件分别组织，简单静态展示可适度合并。图表核心算法保持行为，不随目录调整重写。
- 子组件优先接收明确的 props、发送明确的事件；少量业务容器可以使用对应 store。停止将整个 runtime 展开到模板上下文，也不通过大量透传参数模拟原来的全局对象。
- 局部交互状态如搜索框、展开项、就地编辑输入归所属组件；需要跨页面保留的业务草稿归 store。
- 新建和实质改写的组件使用标准 `<script setup lang="ts">`；现有组件随职责拆分迁移，避免只为语法变化扩大差异。
- CSS 先保持现有加载顺序和选择器含义，组件专属样式再随组件迁移；跨子组件规则明确保留全局或使用适当的深层选择，防止简单加 `scoped` 后样式失效。

### 状态和生命周期

沿用 Vue 的响应式能力组织轻量 store，本次不引入额外状态管理框架。页面和导航协调层调用 store 操作；store 不导入 router，底层 HTTP、实时传输和核心算法不依赖页面，避免循环依赖。

路由是当前页面和资源身份的唯一来源，移除可独立写入的 `state.view`。临时兼容门面可用于分步迁移，但最终删除 `runtime.ts` 的导航及全量状态入口，不保留两套状态同步机制。

应用初始化负责元数据、资产和实体底账，路由负责显式资源装载。WebSocket 与计时器由应用生命周期统一管理，切换页面不反复断连或清空历史；销毁、初始化失败后重试及 Vite 热更新须防止重复监听和重复连接。

首次初始化由入口或路由守卫调用同一个幂等初始化服务，不依赖 `App.onMounted`。入口可以等待 `router.isReady()`，但守卫等待的初始化不得反向等待组件挂载；初始化失败必须呈现可重试状态。

## 4. 路由与资源装载契约

采用 `createWebHistory()`。嵌套公共布局只包裹编辑页、工坊和数据页，显示态使用独立布局。导航使用命名路由和 RouterLink，业务层不写 `location.hash`。

| 路径 | 行为 |
| --- | --- |
| `/` | 进入上次有效大屏的编辑态；无有效记录时进入默认大屏，并替换为标准地址 |
| `/viewer` | 显示态入口，按上次有效记录或默认大屏解析 ID，再替换为标准显示地址 |
| `/screens/:screenId/edit` | 打开指定大屏编辑态 |
| `/screens/:screenId/view` | 打开指定大屏显示态 |
| `/workshop` | 返回本会话保留的模板草稿，使用 `replace` 转到 `/workshop/:templateId`；新建草稿或没有草稿时转到 `/workshop/new` |
| `/workshop/new` | 新建模板草稿；保留本会话已有的新建草稿，主动“新建”操作才重置 |
| `/workshop/:templateId` | 加载指定已有模板；`new` 为保留静态路径 |
| `/data` | 数据状态 |
| 其他路径 | 显示页面不存在及明确返回入口 |

资源 ID 校验、加载、失败展示与地址一致。显式无效 ID 或资源不存在时不回退默认资源；网络异常显示加载失败和重试，不能误报为资源不存在。缺少必要路由参数的地址进入错误页。

成功新建或导入大屏后导航到新资源；模板首次保存、另存为成功后用 `replace` 更新为保存后的模板地址，失败时保持原草稿和地址。初始化失败或保存失败不提前改变保存基线。

同一大屏编辑态与显示态共享当前内存草稿，包括未保存的排版和对象指派；复制 URL 到新窗口只加载已保存配置，不传输内存草稿。前进后退执行同样的装载和草稿保护逻辑。

异步加载使用取消信号或请求序号，只允许当前目标的结果提交状态；快速从 A 切到 B 时，A 的慢响应不能覆盖 B。资源装载失败时保留原草稿，但目标页只能显示目标错误，不能显示旧资源冒充目标。保存期间的响应按资源 ID 和提交快照更新，防止把保存期间新增修改误标记为已保存。

### 旧地址兼容

- 在根入口识别旧 `#editor`、`#viewer`、`#workshop`、`#data` 及 `?screen=...`，转换一次后使用 `replace`，不制造重复历史记录。
- 旧大屏入口显式提供 `screen` 时优先使用该 ID，非法或不存在仍显示错误；未提供时才使用上次有效记录或默认大屏。
- 旧工坊和数据入口转到对应页面；新标准资源路径的参数不被遗留查询参数覆盖。
- 已有未知 hash 入口明确提示无效页面，不无条件当成编辑态。
- `tools/launcher.mjs` 在演示模式打开 `/viewer`，真实模式打开 `/`；两个入口解析资源后替换为标准地址，启动器不再生成 `#viewer`。

### 服务端配合

修改 `server/index.mjs`：仅对浏览器前端页面请求返回 `index.html`；`/api`、`/api/*`、`/ws`、静态资源目录与带文件扩展名的缺失资源保留正确错误响应。只接受适当的 GET/HEAD 页面请求，保留现有路径越界检查、同源检查和响应安全头。

Vite 基础路径、静态资源地址与路由 history 基础路径统一按站点根目录部署，不新增子目录部署能力。生产构建后直接访问深层地址、刷新页面和资源懒加载均须验证。[Vue Router 对 history 模式与服务器回退的说明](https://router.vuejs.org/guide/essentials/history-mode.html)

## 5. 草稿与离开保护

| 操作 | 处理 |
| --- | --- |
| 同一大屏编辑态与显示态互切 | 保留内存草稿和撤销栈，不重复加载 |
| 进入数据页或工坊后返回大屏 | 保留大屏草稿；模板草稿也独立保留 |
| 打开同一个模板 | 返回当前草稿，不用服务端副本覆盖 |
| 打开另一大屏或模板、主动新建、导入替换当前大屏 | 仅针对将被替换的脏草稿提示；取消时保持地址、内容和历史状态 |
| 保存失败或用户取消 | 保留草稿及未保存标记 |
| 刷新、关闭浏览器、离开站点 | 任一草稿未保存时调用浏览器原生离开保护，提示文案由浏览器决定 |

本次只保留当前大屏、当前模板各一份内存草稿，不扩展为多文档缓存；不将草稿写入 localStorage、不自动保存、不承诺刷新后恢复。显示态仍能看到同一会话的未保存大屏内容，维持现有使用体验。

路由守卫和业务入口共用同一套草稿替换判断，避免弹两次确认；保存、导入等进行中阻止会产生身份冲突的替换操作，待成功或失败后再允许操作。

## 6. 统一构建与离线开发包

### 命令及构建产物

| 命令 | 目标职责 |
| --- | --- |
| `npm run dev` / `npm run dev:live` | 真实模式开发入口，后者作为明确别名 |
| `npm run dev:demo` | 演示模式开发，前后端联动与 HMR |
| `npm run typecheck` | 类型检查 |
| `npm run format` / `npm run format:check` | 写入格式与只读格式检查 |
| `npm test` | 现有核心算法单测及本次必要纯逻辑单测 |
| `npm run build` | 类型检查、Vite 客户端构建、服务端及启动器发布装配 |
| `npm run start` / `npm run start:demo` | 启动统一发布产物 |
| `npm run package:offline` | 校验准备好的离线资源并装配开发包，缺资源明确失败 |

`build:vite`、`start:vite` 等旧命令保留为对应统一入口的兼容别名，移除旧双轨含义。客户端采用唯一 Vite 产物目录 `../liteCodeTool_tmp/dist/`；发布装配复制该产物到 `../liteCodeTool_tmp/release/app/web/`，这是同一次构建的发布副本。

改写 `tools/build.mjs` 为标准构建与发布装配入口，删除 Vue 正则解析、自制模板编译和模块加载器。发布端使用带齐依赖的固定 Node 运行环境；共享 `engine/core.ts` 的服务端交付形式需与 Node 启动参数一致，采用标准 TypeScript 编译输出并转换引用，不保留 vendor 编译器或字符串拼装前端模块。

确认所有引用迁移完成后清理仅供旧编译链使用的 `vendor` 资源及相关许可条目；仍被服务端实际使用的 ws 等资源保留到其引用明确迁移完成。更新 `THIRD_PARTY_NOTICES.md`，不能先删资源后修构建。

### Windows x64 离线交付内容

- 项目源码、`package-lock.json` 和基于该锁文件在 Windows x64 准备的完整 `node_modules`，包含开发依赖及构建工具的平台二进制。
- 固定兼容版本的 Node 与 npm；明确 Node、Windows 架构和源码/锁文件版本，保留下载来源、版本和文件校验值。
- Vue 官方扩展和 Prettier 扩展的 VSIX，携带必需的扩展依赖；VS Code 和调试浏览器提供版本要求及可离线安装资源的准备说明，内网机器必须能离线完成准备。
- 开发环境启动入口：只为本次进程设置工具链环境，显式选择离线 Node，不能依赖外网代理、全局 npm 包或机器专属路径，不静默修改系统 PATH。
- 外部文件清单与校验信息；Node、VSIX、打包中间物、压缩包存放在 `../liteCodeTool_tmp/`，不进入源码仓。

开发包可组织为 `工具链目录 + liteCodeTool/源码 + 同级 liteCodeTool_tmp/ + 同级 liteCodeTool_datas/`。解压后仍满足源码、临时产物和用户数据隔离。开发者已有的真实配置、Token 和实体数据不能随包分发。

带入内网后不要求重新 `npm install`，构建、调试和格式化均使用包内依赖；不使用会隐式联网下载的 npx 调用。增加或升级依赖时在可联网的同平台环境重新准备完整开发包，并更新锁文件与清单。

### 调试设计

- 提供“前后端联调（演示）”默认入口，另有真实模式与单独前端/后端入口。
- 调试器启动开发协调进程，并覆盖实际处理 HTTP 的 Node 子进程；前端以 Edge 调试为默认，Chrome 为可用替代配置。
- 浏览器在开发服务真正就绪后打开；后端失败、端口占用或工具链缺失时显示明确错误，不无限等待、不自动结束占用端口的其他进程。
- 使用 `${workspaceFolder}` 和相对工具链位置，前端源码映射定位 `.vue` 和 `.ts`；后端命中实际 `.mjs` 与共享 TypeScript 源码。不能仅以浏览器能打开作为调试验收。
- 停止调试时清理本次启动的 Vite、后端及监听端口；已有独立服务使用明确的附加调试入口，不误杀其他服务。
- 调试浏览器配置、日志和诊断输出放外部临时目录；运行时数据明确放外部数据目录。真实模式凭据不写入受控编辑器配置。

VS Code 已提供浏览器与 Node 调试能力，项目配置负责启动、源码映射和进程协同。[浏览器调试说明](https://code.visualstudio.com/docs/nodejs/browser-debugging)、[Node 调试说明](https://code.visualstudio.com/docs/nodejs/nodejs-debugging)

### 格式化规则

新增 `.prettierrc.json`、`.prettierignore`、`.editorconfig`，统一两空格缩进、脚本单引号、分号、合理换行宽度，Vue 模板属性分行；VS Code 保存时格式化使用项目本地 Prettier，与命令行结果一致。[Prettier 配置说明](https://prettier.io/docs/configuration)

格式化覆盖项目自有 Vue、TS、JS/MJS、CSS、JSON 和当前 HTML 源文件；排除第三方 vendor、锁文件、生成文件、历史归档、AGENTS.md 及外部目录。不增加重型 lint 体系、Git 钩子或 CI 门禁。格式化修正与业务重构按阶段检视，避免遗漏行为变化。

## 9. 实施顺序

1. 记录现有核心测试、类型检查和 Vite 构建基线，检查已有未提交改动；失败项如实区分原有问题与本次引入问题。
2. 建立统一 Vite 发布与标准组件编译基础，加入路由和格式化依赖及配置，更新发布启动入口。
3. 拆分业务状态、网络和应用生命周期，维持保存冲突检测、快照撤销和实时数据行为。
4. 接入资源路由、旧入口转换、草稿保护和服务端回退，再拆分独立页面、布局与复杂子组件，移除旧导航状态。
5. 整理样式、格式化自有源码，检查搜索残留，确保无自制模块加载器和手写 hash 导航。
6. 配置 VS Code 调试、离线包准备和验证入口，同步原型及开发文档。
7. 执行下面的验收，在外部临时目录形成验证记录；全部通过后更新 ADR 实施状态并归档本方案。

步骤可在同一阶段内交替推进，但必须先具备标准编译能力，再迁移被旧编译器禁止的组件语法。全过程由当前 Codex 实例完成，不委派子代理。

## 10. 验收标准

### 自动检查

- `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 全部通过；兼容构建命令实际指向同一链路。
- 仅为旧地址转换、资源 ID 解析、草稿替换判断等被提取的关键纯函数补充必要单测；不搭建 UI/E2E 测试体系。
- 源码不再出现可独立写入的页面模式、业务函数修改 hash、自制 Vue 模板编译器；团队配置中没有个人机器绝对路径。

### 路由和草稿验收

| 场景 | 必须达到的结果 |
| --- | --- |
| 新路由直接打开、刷新、前进后退 | 开发和发布服务都定位到同一资源，正常渲染 |
| 旧 hash 和 `?screen=` 链接 | 标准化地址正确，旧无效 ID 不被默认资源掩盖 |
| 无效页面、缺失资源、网络失败 | 区分对应错误，提供返回或重试入口；API 与资源缺失不返回页面 HTML |
| 修改大屏后切显示态、工坊、数据页再返回 | 修改和撤销记录仍在，实时连接不重复创建 |
| 修改模板后离开再返回 | 草稿保留；打开另一模板时确认保护生效 |
| 取消替换、保存失败、刷新关闭 | 取消不改变地址和内容；失败不清草稿；浏览器离开保护生效 |
| 快速切换资源、保存中产生新修改 | 慢响应不覆盖新目标；新修改不会误标记为已保存 |
| 模板首次保存、另存为、大屏新建和导入 | URL 与新资源 ID 一致，刷新可加载已保存资源 |

### 功能与调试验收

- 人工检查拖入组件、移动缩放、卡头就地编辑、槽位切换、曲线双轴、表格设置、撤销重做、导入导出及显示态行为，与改造前契约一致。
- VS Code 启动演示联调，分别在 Vue 点击处理、前端 TypeScript 操作、后端 API 处理处命中源码断点，能查看变量并单步；停止后无本次遗留开发进程。
- 保存 Vue 文件触发格式化和 HMR，前端断点在热更新后仍能命中；真实模式能启动且不混入演示数据目录。

### 离线与可迁移验收

- 在外部临时目录解压到新的含中文和空格路径，不借用原仓的 `node_modules`、全局 npm 工具或个人绝对路径，启动开发、格式化、类型检查、核心测试和生产构建。
- 使用离线扩展安装资源完成编辑器准备；无外网条件下运行两端调试并验证源码断点，回环 HTTP/WebSocket 保持可用。[VSIX 安装说明](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace)
- 验证方式应隔离测试进程的外网访问或在独立断网环境执行，不擅自修改用户机器全局网络设置。仅设置 npm offline 或查看配置，不能当作完整断网验收证据。
- 运行包能独立离线启动。自带演示和界面资源不依赖 CDN；用户主动配置的外部图片、真实外部数据源仍需要相应内网可达性，不属于工具链离线资源。
- 如环境无法完成实际 VS Code 断点或断网验证，记录具体未验项，不能宣称验收全部通过或提前归档。
