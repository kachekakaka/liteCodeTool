# 轻量化低代码大屏平台实施方案 (AIS 船舶监控典型应用)

## 问题陈述 (Problem Statement)

在船舶监控（AIS）等指挥大屏业务中，现场大屏界面种类繁多、指标要求多变。传统硬编码开发模式周期长、修改成本高，无法灵活应对以下痛点：
1. **组件复用率低**：针对单船监控、双船对比等重复样式，缺少可复用的卡片蓝本，每次开发都要重复画页面；
2. **动静绑定割裂**：大屏在投屏监控（显示态）下无法应对现场突发调度（如突然进港一艘重点新船，无法在运行态快速将卡片切换绑定至该船）；
3. **数据驱动卡顿与缺字段失真**：后端通过 WebSocket 高频推送海量船舶增量数据，传统遍历组件树刷新容易造成界面顿挫；同时若单纯依赖增量推送，用户在界面调整指标（如改看经度）或刚打开页面时容易因未上报而呈现空白。

---

## 解决方案 (Solution)

构建一套**轻量、解耦、零外部数据库依赖的低代码大屏平台**：
1. **双层解耦体系**：
   - **组件工坊**：由基础原子控件（数值、文本、时间、指示灯、表格、曲线）组合封装为“组件模板”，声明抽象对象槽位（如“对象1”、“对象2”）；
   - **大屏画布**：将组件模板作为通用资产拖拽至画布生成“组件实例”，在大屏级别独立赋予具体实体（如船号 MMSI），保存大屏绝不污染原始组件库；
2. **动静双态分离**：
   - **编辑态**：提供全功能拖拽网格编排、组件属性设置与槽位默认值配置；
   - **显示态**：沉浸式监控投屏，组件右上角提供轻量槽位快捷切换（支持输入即搜与新船动态发现），支持一键将当前视角保存为默认大屏；
3. **闭环可靠的数据总线**：
   - **HTTP 查初始底账 + WebSocket 听增量改写**：换船或进页面时通过 HTTP 拉取最新已知全量快照，后续 WebSocket 增量更新；本地有数据秒级回显，若后端从未提供则老实展示 `--` 空值占位，杜绝臆测；
   - **前端响应式实体数据池 (Entity Store)**：按数据类型和唯一标识建立响应式索引，控件按需监听局部刷新，保障大屏高频推流下的丝滑体验；
4. **轻量纯粹落地**：前端采用 Vue 3 + Vite + TypeScript，后端采用轻量 Node.js，数据纯 JSON 存储于外部数据目录（`../liteCodeTool_datas/`），零配置无外部数据库。

## 用户故事 (User Stories)

### 一、组件制作与资产沉淀 (Component Authoring)
1. 作为一名组件设计者，我想要在独立的工作台中将数值框、文本框、指示灯等基础控件拼装为复合卡片，以便于沉淀规范统一的业务组件资产。
2. 作为一名组件设计者，我想要在组件中声明抽象的“对象槽位”（如对象1、对象2）并将子控件绑定至槽位的指定字段，以便于该组件能通用适配同类型的任意业务实体。
3. 作为一名组件设计者，我想要将控件直接绑定到非实体的“全局数据模式”（如全港船舶统计、系统运行告警），以便于展示与特定实体无关的宏观大盘信息。
4. 作为一名组件设计者，我想要在表格和曲线控件中配置“多对象横向对比”或“基于条件动态加载对象集”，以便于支持多船对比及分类船舶清单滚动展示。

### 二、大屏设计与编排 (Screen Canvas Editing)
5. 作为一名大屏制作人员，我想要在画布上自由拖拽组件资产库中的卡片并调整大小、层级与位置，以便于快速拼装出符合特定指挥室要求的大屏界面。
6. 作为一名大屏制作人员，我想要在大屏编辑态下为某个卡片实例预设具体的船舶编号（如从候选船舶列表中选择），以便于大屏发布后默认呈现指定重点船只。
7. 作为一名大屏制作人员，我想要在大屏编辑态下随时调整某个数值框所绑定的展示字段（例如将航速换成经度），以便于根据业务侧重点微调看板内容。

### 三、现场监控与动态调度 (Runtime Monitoring & Viewing)
8. 作为一名大屏监控值班员，我想要在显示态下获得沉浸式的全屏展示效果并锁定画布排版，以便于投屏监控时防止误触移动组件。
9. 作为一名大屏监控值班员，我想要在显示态下直接在卡片角落输入船名或编号快速切换监控对象，以便于海上突发警情时能一秒盯紧目标船只。
10. 作为一名大屏监控值班员，我想要在显示态下将当前临时切换好的船只布局一键“保存为当前大屏默认配置”，以便于常态化固化监控视角且无需重启任何服务。
11. 作为一名大屏监控值班员，我希望即使后端尚未推送新切船只的部分字段时，系统也能通过初始底账或显示 `--` 占位符优雅兜底，以便于大屏界面绝不出现崩溃或错乱。

## 实现决策 (Implementation Decisions)

### 1. 架构决策 (Architectural Decisions)
- **模板与实例彻底解耦 ([ADR 0001](file:///d:/Projects/litleTools/liteCodeTool/docs/adr/0001-template-instance-and-entity-store.md))**：组件模板（Component Template）是资产库里的抽象蓝本；大屏上的每个卡片是组件实例（Component Instance）。大屏保存时仅序列化实例的属性与槽位值，绝不改写模板定义。
- **核心技术栈选型 ([ADR 0002](file:///d:/Projects/litleTools/liteCodeTool/docs/adr/0002-vue3-vite-nodejs-tech-stack.md))**：前端采用 Vue 3 + Vite + TypeScript，后端采用轻量级 Node.js（提供 REST API 与原生 WebSocket 服务）。
- **底账与增量结合的数据流机制 ([ADR 0003](file:///d:/Projects/litleTools/liteCodeTool/docs/adr/0003-incremental-push-with-snapshot-fallback.md))**：HTTP 获取全量初始快照作为底账，WebSocket 仅推送增量更新合并入前端响应式实体数据池 (Entity Store)；无数据字段统一显示 `--`。
- **纯 JSON 文件外部持久化 ([ADR 0004](file:///d:/Projects/litleTools/liteCodeTool/docs/adr/0004-json-file-persistence.md))**：零数据库依赖，大屏配置与组件资产存储于同级外部数据目录（`../liteCodeTool_datas/`），实现代码与数据的完全解耦。

### 4. WebSocket 通信协议
WebSocket 仅推送增量更新包，客户端统一消费：
```json
// 针对具体实体（如船只）
{
  "type": "vessel",
  "id": "413000001",
  "timestamp": 1725600000000,
  "data": { "speed": 13.8, "lat": 31.2356, "lon": 121.4589 }
}

// 针对全局指标（非实体）
{
  "type": "port_stats",
  "timestamp": 1725600000000,
  "data": { "total_vessels": 185, "cargo_count": 56 }
}
```

### 5. 核心前端模块划分
- **`src/engine/store/entityStore.ts`**：轻量响应式实体数据池，对外提供 `getEntity(type, id)`、`getGlobal(type)`、`applyUpdate(type, id, data)` 及快照查询回退能力；
- **`src/engine/dispatcher/wsClient.ts`**：WebSocket 客户端，负责连接保活、重连与增量数据分发写入 `entityStore`；
- **`src/engine/binding/resolver.ts`**：数据绑定解析纯函数，根据控件绑定配置，从实体池中计算当前应渲染的显示值与单位；
- **`src/components/controls/`**：7 种基础原子控件（`ImageBox.vue` 图片/动图控件，支持静态图片与雷达/波纹动效；`TextBox.vue` 文本框，支持静态固定录入与动态字段绑定双模；`NumberBox.vue` 数值框；`TimeBox.vue` 时间框；`StatusLight.vue` 指示灯；`TableBox.vue` 表格；`LineChart.vue` 曲线）；
- **`src/views/workshop/`**：组件工坊工作台，负责组件模板编辑与入库；
- **`src/views/canvas/`**：大屏制作与运行工作台，包含“编辑态”与“显示态”视图切换器。

## 测试决策 (Testing Decisions)

根据项目 `AGENTS.md`“轻量实用，杜绝过度治理”原则，**不引入 UI E2E、Puppeteer 或复杂集成门禁**，全系统只设立**唯一一个极高价值的测试切面（High-Level Seam）**：

### 核心测试切面 (Single Seam): 数据绑定解析与实体数据池响应式引擎 (`resolver & entityStore`)
- **测试标准**：只测试公开的输入输出行为，不测内部私有状态：
  1. **实体字段正常解析**：向 Store 写入底账，resolver 能正确提取对应槽位字段的值与单位；
  2. **WebSocket 增量合并响应**：向 Store 输入增量字段，验证原有字段不丢失、变动字段准确更新；
  3. **空值与缺失字段兜底**：当实体未上报某字段或 Store 为空时，resolver 严格输出 `--` 空值占位符，绝不抛出异常；
  4. **全局非实体字段解析**：验证非实体模式下的字段绑定正常工作；
  5. **槽位重定向切换**：修改组件实例的 `slotBindings` 指向另一艘船，验证 resolver 瞬间返回新船的对应属性。
- **测试模式**：使用 Vitest 编写单个精简、短小、针对性强的测试套件（运行时间 < 1 秒），纯函数化无浏览器环境依赖。

## 范围外说明 (Out of Scope)

1. **复杂 GIS 矢量海图渲染**：首期聚焦大屏卡片与图表联动，不引入重型 WebGIS/三维地球引擎；
2. **多租户权限与复杂审批流**：首期面向轻量化大屏指挥，不增加复杂的 RBAC 用户体系；
3. **外部重型数据库驱动**：坚决不引入 MySQL、Oracle 等外部数据库软件，保持纯 JSON 文件持久化；
4. **重型构建流水线与 UI 视觉回归测试**：坚决不编写无意义的 DOM 点击测试。
