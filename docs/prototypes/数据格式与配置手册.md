# 数据格式与配置手册

本手册说明当前前后端交换和持久化的全部业务数据种类、配置关系与操作方式。字段名、类型及必填性集中在 [完整字段表](数据结构字段表.md)，请求方法、路径、响应外壳和错误集中在 [后端接口契约](后端接口契约.md)。[示例目录](examples/) 提供可复制的 JSON；时间戳示例发送前请替换为实际源时间。

## 1. 数据全景与文件对应关系

| 数据种类 | 结构 | 来源 / 用途 | 是否持久化 |
| --- | --- | --- | --- |
| 模式与字段定义 | Schema、Field | 字段选项、身份定义、输入类型校验 | schemas/default.json，数组 |
| 业务增量 | Envelope | HTTP ingest、WebSocket update | 合并后进入快照，不逐条存日志 |
| 初始底账 | Envelope + fieldTimestamps | bootstrap、单实体查询、进程恢复 | entities/snapshot.json，数组 |
| 前端实体池 | EntityRecord、Point | 最新值、字段时间、曲线历史 | 浏览器内存；历史不落盘 |
| 组件模板 | ComponentTemplate、Slot、Control | 可重复使用的控件与槽位布局 | templates/{id}.json |
| 大屏 | ScreenConfig、ComponentInstance、Override | 模板引用、位置、目标指派、私有覆盖 | screens/{id}.json |
| 完整导入导出包 | format + screen + templates | 跨大屏/系统转移配置 | 用户下载的 .litecode.json |
| 接入单位 | default + sources | 外部米制数据换算为平台单位 | ingestion-units.json |
| 运行接入凭据 | ingestToken | 启动器读取或生成 | connection.json，仅真实目录 |
| 升级与锁 | 版本标记、迁移日志、进程锁 | 兼容旧目录、避免同时写同一目录 | 隐藏 JSON 文件，程序管理 |
| 界面会话状态 | 路由、草稿、选择、视口、消息流队列 | 当前窗口交互 | 多数仅内存；少量 localStorage 记忆 |
| 交付清单 | 包 manifest、资源来源/摘要 | 核对版本和文件完整性 | 离线包根目录，与业务数据无关 |

实例 position 相对大屏，控件 style 相对模板内部画布；二者均是逻辑像素，浏览器缩放不改配置。模板被多个大屏共享，修改模板会影响这些引用；修改实例覆盖只影响当前实例。

## 2. JSON 和 Java 类型对应

| JSON / 前端类型 | Java 建议 | 注意事项 |
| --- | --- | --- |
| string | String | ID 保留前导零，MMSI 不转整数 |
| number（业务量） | Double 或合适的数值类型 | JSON 输出必须是数值，不能加单位或引号；拒绝 NaN/Infinity |
| number（时间） | long / Long | Unix 毫秒，不是秒 |
| boolean | Boolean | 可选字段不能用 false 代替未出现 |
| null | 显式 null 节点 | data 中表示清空；覆盖绑定时表示取消绑定 |
| 缺失字段 | containsKey/JsonNode.has 判定 | 增量保留旧值，覆盖项继承模板 |
| Record<string,T> | Map<String,T> | 保留“无键”和“键存在但值为空”的差别 |
| 有序数组 | List<T> | 顺序影响曲线、表格列、规则匹配和控件排列 |

Scalar 在配置模型中允许 string、number、boolean、null。但当前业务 Schema 只定义 string、number、enum、datetime，HTTP 业务接入没有 boolean 字段类型，因此不能因 Scalar 包含 boolean 就向任意业务字段发送布尔值。

## 3. 模式定义 Schema

完整内置字段与枚举见 [内置字段表](数据结构字段表.md#内置业务模式完整字段)，可读取的完整 JSON 为 [schemas.json](examples/schemas.json)。当前模式有 vessel（实体船舶）、projectile（实体飞行目标）、port_stats（全局统计）、event_log（全局最新消息）。

- type 对应 Envelope.type，name 为中文显示名；isEntity=true 要求 Envelope.id，false 禁止提供 id。
- idField 表示与记录 ID 一致的业务字段；船舶 mmsi 若出现在 data 中，必须等于 Envelope.id，不能清空。它不表示 data 每次都必须带该字段。
- targetIdField 是业务目标字段，sourceField 是物理来源字段。projectile 使用 batch_no、source，没有 idField。
- Field.type=number 接收有限 JSON 数值或 null；其他三类接收字符串或 null。datetime 必须是可解析的日期字符串，建议使用带时区的 ISO 8601，例如 `2026-09-09T10:00:00+08:00`。
- precision 是默认显示小数位，不会对存储和推流数值做四舍五入。unit 是显示单位；仅改 unit 文本不会进行输入数据换算。
- enum.options 用于界面候选选项，当前接入并未强制值在 options 内。新数据来源可发送其他字符串，但需遵循身份和长度规则。
- 当前没有数值上下界、正数校验、经纬度范围或强制整数计数规则；业务系统如增加规则，应明确这是 Java 侧的新约束。

新增模式或字段：先停服务，备份实际数据目录，修改 schemas/default.json 中的数组，保证 type/字段 key 唯一合法，元数据类型正确，再重启并通过 GET /api/schemas 核对。运行中改文件不会热更新内存模式。再在工坊增加对应槽位、字段绑定和控件并保存；接入 data 只能用已声明字段。改变字段类型或移除字段前，应处理已有快照、模板和覆盖引用。已有目录的默认补种不会覆盖你的模式配置，不要将修改 server/defaults.mjs 误当作更新现存用户目录的方式。

## 4. 增量与底账 Envelope

一次 HTTP 接入仅对应一种模式的一条记录。所有实际字段位于 data，对象/数组不能作为字段值。

```json
{"type":"vessel","id":"413000001","timestamp":1788940000000,"data":{"mmsi":"413000001","vessel_name":"测试船","vessel_type":"商船","speed":12.5,"heading":90,"lon":121.5,"lat":31.2,"status":"在航","update_time":"2026-09-09T10:00:00+08:00"}}
```

```json
{"type":"port_stats","timestamp":1788940000000,"data":{"total_vessels":10,"cargo_count":6,"fishing_count":3,"warning_count":1}}
```

```json
{"type":"event_log","timestamp":1788940000000,"data":{"time":"2026-09-09T10:00:00+08:00","level":"info","source":"接入服务","content":"开始接收数据"}}
```

全局记录内部键是 `_global`，外部 Envelope 必须省略 id，不要发送 `"id":"_global"` 或 `"id":null`。

### 时间、缺失和乱序

timestamp 是源数据时间，不是前端接收时间。HTTP 要求有限数值且不超过服务器当前时间 60 秒；当前实现没有额外要求非负或整数，但对接应使用实际 Unix 毫秒整数。

第一次发送 `{"speed":10,"altitude":1}`，下一次只发送 `{"altitude":1.2}`，speed 保持 10，且 speed 的字段时间仍是第一次时间。发送 `{"altitude":null}` 会清空高度，显示 `--` 并中断数值曲线；缺失字段不会清空。相同字段的新时间必须**严格大于**已存字段时间，同时间戳不同值和更旧值均忽略；未被更新的另一字段仍可接受比它自己的旧时间新的值。

快照的 timestamp 为各字段时间最大值，fieldTimestamps 保存每个字段真实源时间。Java 不应将所有字段时间覆盖成快照时间，否则会误阻止合法的后续增量。外部发送者不能指定这些时间；HTTP 入口剥离客户端 fieldTimestamps 后统一使用 Envelope.timestamp。

快照只补最新值，不产生数值历史。数值历史每字段最多 7200 点且按新点时间裁去一小时前数据；只在内存保留。重启、刷新和重连没有历史补齐接口。曲线可能需要等待连续新数据后才出现，这不是读取快照失败。

### 多来源飞行目标

```json
{"type":"projectile","id":"P-101-radar2","timestamp":1788940000000,"data":{"batch_no":"P-101","source":"雷达2","altitude":1.2,"speed":360,"heading":90,"lon":121.5,"lat":31.2,"status":"跟踪","update_time":"2026-09-09T10:00:00+08:00"}}
```

同批号的遥测记录应使用另一个 id，例如 P-101-telemetry1，并将 source 设为 遥测1。三个维度分别为：

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| type + id | projectile + P-101-radar2 | 唯一物理记录键 |
| data.batch_no | P-101 | 大屏选择的业务目标，可有多个来源记录 |
| data.source | 雷达2 | 同一目标的来源，最长 80 字符 |

同一批号、同一来源只能有一条记录 ID。记录建立后不能更换或清空 batch_no/source；需要新身份时使用新 ID。后续增量可省略身份字段并继承已有身份。兼容单源首次接入：省略批号采用 id，省略来源采用空串；多源接入推荐首包明确带齐二者。

## 5. 高度、速度与接入单位

平台存储、快照、历史、规则比较和推流中的 projectile.altitude 始终使用 **km**，projectile.speed 使用 **km/h**。船舶 vessel.speed 使用**节**，不参与飞行目标单位换算。update_time 是显示用日期字段，不替代 Envelope.timestamp。

真实来源发送米、米/秒时，在当前真实数据目录创建或修改 ingestion-units.json：

```json
{"default":{"altitude":"m","speed":"m/s"},"sources":{"雷达2":{"altitude":"km","speed":"km/h"},"遥测1":{"altitude":"m"}}}
```

按字段合并优先级：平台默认 km/km/h → default → 当前来源的 sources 配置。高度仅支持 m/km，速度仅支持 m/s/km/h；m 乘 0.001，m/s 乘 3.6，null 保持 null。缺文件等同 `{}`。停服务修改后重启生效；该配置没有 HTTP 编辑接口。只在外部真实接入入口转换一次，底账、WebSocket 和演示数据不再次转换。

如果来源已经切换为 km/km/h，须同步修改单位文件；仅改控件单位文本会把数值标成错误单位。相同物理来源名称使用不同单位时，应先统一来源侧协议，当前配置按 source 名称全局匹配。

## 6. 模板、槽位和控件配置

完整 ComponentTemplate、Slot、Control、Binding、ControlProps、Series 字段见 [字段表](数据结构字段表.md)。最小高度监控模板与大屏示例在 [flight-screen.litecode.json](examples/flight-screen.litecode.json)，可直接导入。

模板结构：id、name、category、layout、slots、controls，加可选 showHeader、decoration、subTitle。name 为非空且不超过 120 字符；layout.width 80～3840，height 60～2160；最多 20 槽位、100 控件。槽位 ID 在模板内唯一，只能指向实体模式；全局绑定不需要槽位。控件 ID 在模板内唯一。

Control.style 必须有 x/y/w/h，w/h>0，x/y>=0，并在模板逻辑画布内（允许 0.1 像素浮点误差）；fontSize、color 可选。props 必须是对象，即使没有属性也传 `{}`。geometry、position、layout、resolution 都不是 CSS 字符串，不能填写 `100%`、`1920px`。

Binding 两种写法：

```json
{"target":"slot","slotId":"target1","field":"altitude"}
```

```json
{"target":"global","schemaType":"port_stats","field":"total_vessels"}
```

前者从实例槽位指派找到目标记录，后者读取全局记录。引用字段必须存在，global 不可指向实体模式。

### 通用显示与覆盖规则

- sourceMode=static 使用 staticValue；dynamic 使用 binding。省略 sourceMode 时有 binding 才按动态兼容。clock 启用时使用当前时钟。
- labelMode/unitMode=auto 继承字段元数据，custom 使用 label/unit；precision 为 0～8 整数，null 或省略表示继承。staticValue=null 显示空值；自定义空标签、空单位可隐藏文本。
- staleSeconds 缺省通常为 120 秒，0 关闭，允许 0～86400；使用**字段源时间**判断，而不是最后收到任意数据的时间。
- decoration=card/banner 控制卡片/横幅外观；标题、副标题和 showHeader 可由实例覆盖。subTitle 空串明确隐藏，省略继承；模板也省略时，有槽位为“目标监控”，无槽位为“数据总览”。

### 八类控件属性及默认行为

| type | 主要配置 | 默认与限制 |
| --- | --- | --- |
| text | sourceMode、staticValue、binding、label、clock | 字符串显示；不执行 HTML/脚本 |
| number | 同上，precision、unit、variant、iconType、imageUrl | variant standard/kpi；iconType vessel/cargo/fishing/alert/none |
| time | sourceMode、staticValue、binding、clock | 动态时间格式化为本地中文时间；clock 为当前时间 |
| light | binding、colorRules | 按有序值规则匹配颜色，最多 30 条，颜色 #RRGGBB |
| table | schemaType、columns、filterField/filterValue、pageSize、autoPageSeconds、tableColumnRules、staleEnabled/staleSeconds | 实体模式；严格等值过滤；默认每页 4 行，1～20；按记录 ID 排序；自动翻页 0～120 秒，0 关闭；整行过期默认开启、阈值 120 秒 |
| line | series、lookbackUnit/Seconds/Minutes、gapSeconds、xAxisMode/Field/SlotId/SchemaType | 最多 8 曲线；默认近 20 分钟，秒模式默认 60 秒；分钟 1～60，秒 10～600；默认断线间隔 120 秒 |
| image | imageType、imageUrl、alt | radar/sonar 内置效果；image 使用地址。支持 HTTP(S)、相对地址和 png/jpeg/gif/webp/svg+xml Base64 Data URL |
| stream | schemaType、streamMaxItems、streamAutoScroll | 默认 event_log、50 条、自动滚动；条数为 5～500；队列属于控件会话 |

tableColumnRules 最多 20 列，每列规则最多 30 条，写作 `[{"field":"status","rules":[{"value":"告警","color":"#FF0000"}]}]`。未命中不臆造新状态。数组有顺序。表格行过期按该记录最新有效字段时间判断，和单值字段过期不是同一算法。

指示灯 colorRules 和表格列规则共用比较语法，按数组从前到后取第一条命中：`{"value":">30","color":"#FF0000"}` 表示大于 30；还支持 `>=`、`<`、`<=`，以及 `"10..20"` 的两端包含区间。其他值按标量或其字符串精确匹配，例如 `"告警"` 或数字 1。null 数据和 null 规则不参与匹配；不支持 AND/OR、脚本、字段引用或任意表达式。数值规则使用平台单位，因此高度 `">1"` 表示大于 1 km，速度 `">360"` 表示大于 360 km/h。规则中的单位文本不能写在数值后面。

stream 使用全局最新记录的 time、level、source、content 形成内存消息列表；不是日志数据库，也不是服务端事件查询接口。快速连续推流可能受前端渲染合并影响，不应以它保证逐条消息不丢失。持久化快照仅保留最新全局字段，刷新后不恢复完整列表。

### 折线 Y 轴与双轴航迹

```json
{"xAxisMode":"time","lookbackUnit":"minute","lookbackMinutes":20,"series":[{"target":"slot","slotId":"target1","field":"altitude","label":"高度","yAxis":"left","color":"#3BD5FF","filterSource":"雷达2"},{"target":"slot","slotId":"target1","field":"speed","label":"速度","yAxis":"right","color":"#FFCA57","filterSource":"雷达2"}]}
```

Y 轴数值字段放在 **props.series[].field**；将它仅写在普通 binding.field 不等于配置了一条折线。高度使用 projectile 模式槽位的 altitude，左轴和右轴分别通过 yAxis 指定，默认左轴。每条实体曲线要有 slotId，全局曲线要明确 target=global、schemaType、数值 field。

xAxisMode=field 时以 xAxisField 选数值横轴，结合对应槽位/模式形成航迹；X/Y 点仅在**源毫秒时间完全相同**时配对，不插值、不使用“最近一个点”。经纬度航迹应同一 Envelope 同时上报 lon 与 lat。curve.filterSource（即 Series.filterSource）先用于默认来源，但可被实例来源覆盖。工坊预览目标是会话数据，旧 props.workshopPreviewTarget 会被读写边界移除，不应写入新配置。

## 7. 大屏、实例和来源配置

ScreenConfig：id、name、resolution、background、components，建议明确 bindingVersion=2。name 非空、<=120；分辨率宽 320～7680、高 180～4320；background 为 #RRGGBB；最多 150 实例。

ComponentInstance：instanceId 在大屏内唯一，templateId 指向存在的模板，position 在大屏逻辑边界内，zIndex 可选整数 0～9999；slotBindings 和 controlOverrides 必须有对象（可以为空）。title/subTitle 可选且最多 120 字符。

```json
{"instanceId":"instance_flight","templateId":"tpl_flight","position":{"x":20,"y":20,"w":600,"h":360,"zIndex":1},"slotBindings":{"target1":"P-101"},"slotSourceBindings":{"target1":"雷达2"},"controlOverrides":{"height_value":{"props":{"precision":3,"unitMode":"custom","unit":"km"}}}}
```

slotBindings 的值是业务目标，例如批号 P-101 或 MMSI；不是槽位 ID，也不是每个来源的记录 ID。槽位键必须存在于模板，目标可以暂时没有数据。slotSourceBindings 的三种状态：

| 版本 2 中的配置 | 行为 |
| --- | --- |
| 对象不存在，或不含该槽位键 | 折线继承该序列 filterSource；没有来源约束的控件自动选取 |
| `{"target1":""}` | 显式自动，覆盖曲线固定来源 |
| `{"target1":"雷达2"}` | 只读该目标的雷达2记录，缺失不回退其他来源 |

自动表示选择**单条**记录：优先记录 ID 等于业务目标 ID 的主记录，否则按记录 ID 稳定排序取第一条；不是混合、平均或返回全部来源。指定来源存在多条歧义记录也不返回结果。

无 bindingVersion 的旧配置：空来源转为“无键”，再写 bindingVersion=2。旧指派若是可识别的记录 ID，会规范化为目标 ID，并在来源未显式覆盖时补该记录来源。不要删除版本号后期待空串仍表示显式自动。

controlOverrides 按模板 Control.id 建立稀疏覆盖：style、props 逐键合并；series、columns、colorRules 等数组整体替换；binding 提供时整体替换，null 明确取消，省略继承。不能引用不存在的控件。保存按合并后的有效控件校验，私有覆盖也不能越界或引用无效字段。

嵌入页的临时目标、来源指派仅作用于当前页面内存，刷新恢复已保存配置。它们不是新增的配置格式，也不写入 localStorage 或服务端。

## 8. 导入导出文件

使用 JSON 对象 `{"format":"litecode.screen.v1","screen":{...},"templates":[...]}`，文件扩展名 `.litecode.json`。完整示例：[内置大屏](examples/builtin-screen.litecode.json)、[高度和速度大屏](examples/flight-screen.litecode.json)。

文件包含一个大屏和它引用的模板，不包含 Schema、实时数据、历史、编辑撤销栈或 token。模板和大屏结构均与正常 API 保存一致。导入会分配新资源 ID，不用于覆盖原大屏；具体重映射和响应见接口契约。

图片若写远程 URL，不会被导出包自动下载。离线时可以使用允许的 Base64 Data URL，或者把图片放在部署静态目录可访问的位置；整个 HTTP 配置仍受 2,000,000 字节上限约束。

## 9. 磁盘文件与配置生效方式

持久化目录必须在源码之外，默认是源码同级 liteCodeTool_datas；演示模式使用其 demo 子目录。不要放入 liteCodeTool_tmp。备份、复制目录时先停止对应服务。

```text
liteCodeTool_datas/
  schemas/default.json         # Schema[]，启动时载入
  templates/{id}.json           # ComponentTemplate
  screens/{id}.json             # ScreenConfig
  entities/snapshot.json        # Envelope[]，含字段时间，不含历史
  ingestion-units.json          # 可选输入单位，启动时载入
  connection.json              # 启动器管理真实接入 token
  .server.lock                 # {pid, started}，仅程序管理
  .data-upgrade-v2.json         # {version:2, completedAt}，仅程序管理
  .upgrade-v2/journal.json      # 迁移原文备份/恢复日志，仅程序管理
  demo/                        # 独立演示数据，同结构
```

配置模板、大屏通过 API 保存立即写盘，强 ETag 由文件原文决定；人工改空白也会使 Node 的版本变化。业务快照每 5 秒排队原子落盘并在正常退出时尝试保存。模式和单位必须重启载入。数据目录禁止多个服务同时写入，锁文件用于检测；不得因启动失败直接删除有效进程的锁。

程序首次初始化补默认配置；真实模式没有演示实体，演示模式有内置样例。大屏初始化由一次性升级标记控制，允许用户删空大屏后保持空集合。旧单位升级保留原文 journal、换算已知单位并写完成标记，冲突则停止；具体迁移实现见 [data-upgrade.mjs](../../server/data-upgrade.mjs)。这些恢复文件不是应用配置，不提供手工编辑教程，也不要复制到另一个运行进程中当作新数据。

恢复日志结构是 `{ "status": "pending|recovered|completed", "originals": { "相对JSON路径": "升级前完整UTF-8文件原文或null" } }`，其中 status 实际取三种字符串之一，originals 的 null 表示原文件不存在。完成标记的 completedAt 和锁文件 started 为 ISO 日期字符串，锁文件 pid 为正整数。它们只在 Node 文件存储实现中使用，Java 自选数据库时无需照搬磁盘恢复布局，但需实现对应的事务、并发和数据迁移行为。

`connection.json` 为 `{"ingestToken":"实际随机凭据"}`，只用于运行启动器。直接运行 server/index.mjs 或开发协调器时，须用 INGEST_TOKEN 环境变量传入；后端本身不会自动读取该文件。

## 10. 启动、开发和接 Java 的配置

| 配置 | 读取位置 | 默认 / 生效方式 |
| --- | --- | --- |
| DATA_DIR | 后端、运行启动器、start.mjs | 源码同级 liteCodeTool_datas；演示追加 demo |
| LITECODE_DATA_DIR | 离线 IDE 启动器、VS Code 调试配置 | 转为调试会话 DATA_DIR；命令行直接启动应设 DATA_DIR |
| HOST | 后端、运行启动器 | 0.0.0.0；只影响后端，不改变 Vite 固定监听地址 |
| PORT | 后端、启动器、Vite 代理 | 后端直接启动默认 8787；运行启动器演示 8787/真实 8788；Vite 代理缺省 8787 |
| VITE_PORT | Vite | 5173，端口占用直接失败 |
| INGEST_TOKEN | 后端、启动器 | 直接启动缺省空，真实 ingest 禁用；启动器可生成/读取 connection.json |
| CLIENT_DIR | 后端静态托管 | server/index.mjs 默认源码根 web；start.mjs 指向构建产物 web；开发页面由 Vite 托管 |
| `--demo` | server/index.mjs、server/dev.mjs、tools/start.mjs | 演示模式；不带为真实模式 |
| `--live` / `--no-open` | 运行包 launcher.mjs | 启动器默认演示，--live 真实；--no-open 不自动打开浏览器 |
| `--data-dir <绝对路径>` | 离线开发入口 | 指定源码之外的持久化目录 |

所有环境变量在进程启动前设置，修改后重启。Node 入口不自动读取 `.env`。请勿把真实 token 提交到代码或分享包内。

Windows 示例（包内终端已经设置 Node PATH）：

```powershell
$env:DATA_DIR = 'D:\工作数据\liteCodeTool_datas'
$env:PORT = '8788'
$env:VITE_PORT = '5173'
$env:INGEST_TOKEN = '<至少24字符的实际接入凭据>'
npm run dev
```

Linux ARM64 示例：

```sh
export DATA_DIR="$HOME/liteCodeTool_datas"
export PORT=8788 VITE_PORT=5173
export INGEST_TOKEN='<至少24字符的实际接入凭据>'
npm run dev
```

Windows 用 PowerShell 7，ARM 使用系统 Bash。离线入口、可用命令与环境边界见 [离线开发包使用说明](离线开发包使用说明.md)。调试浏览器 URL 必须同步 VITE_PORT。

只启动前端对接 Java 时，将 PORT 设为 Java 监听端口，然后在源码目录执行 `node node_modules/vite/bin/vite.js`；不要运行同时拉起 Node 后端的 dev 命令。生产时将构建的前端 web 配给 Java 静态托管，并保持相同 `/api`、`/ws` 路径。

## 11. 浏览器内存与本地记忆

路由资源 ID 决定打开哪个大屏。当前大屏/模板草稿、撤销栈、选择项、缩放、工坊预览、曲线历史和消息列表属于前端状态，Java 不应将它们加入保存 DTO。localStorage 仅保存前端选择记忆等少量状态（例如 `litecode.screen.demo/live` 上次选择的大屏 ID），不作为大屏或业务数据真源。嵌入上下文不持久化临时指派。

内存类型 EntityRecord、Point、ResolvedValue 的完整字段也列在字段表，供理解前端计算；它们不是现有接口直接接收的正文。显示缺失值为 `--` 是前端格式化行为，后端应发送 null 或省略字段，不要发送字符串 `"--"` 充当业务数值。
