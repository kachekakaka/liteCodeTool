# 离线开发包使用说明

交付分为 Windows x64 和麒麟/Linux ARM64 两个包，包含当前 Vue/TypeScript 前端、Node 后端、文档、原型、测试、构建脚本、锁定依赖、Node/npm、VS Code、Vue 官方和 Prettier 扩展、依赖恢复缓存；Windows 另含 PowerShell 7。它们是开发源码包，不是之前仅可启动的运行包。按本次需求，Java 只提供 [接口契约](后端接口契约.md)、[数据格式与配置](数据格式与配置手册.md)、[全部字段](数据结构字段表.md)，不包含 Java 环境或 Java 实现。

## 1. 目录与系统条件

```text
解压目录/
  README.md
  manifest.json                      # 平台、源码提交、未提交状态、逐源文件摘要
  dev.cmd 或 dev.sh                  # 开发、检查、构建、恢复依赖命令
  打开开发环境.cmd 或 .sh            # 隔离 VS Code
  setup.sh                           # ARM 首次展开环境
  liteCodeTool/                      # 完整当前源码、node_modules、文档和示例
  toolchain/                         # Node/npm、VS Code、扩展、工具链资源及缓存种子
  liteCodeTool_tmp/                   # 启动后创建，构建、编辑器状态及缓存
  liteCodeTool_datas/                 # 启动后创建，可用 --data-dir 改到其他位置
```

源码不含 .git 历史、准备机用户数据、.env 或真实凭据；源码 manifest 记录本次基准提交和当前未提交改动。可以独立编辑、调试、构建，版本管理工具按团队习惯自行使用。

Windows 为 x64 系统；Linux 包为 **aarch64 + glibc**，不适用于 Windows ARM、32 位 ARM 或 musl。VS Code 需要桌面环境和系统图形库，官方列出的最低库版本为 GLIBC 2.28、GLIBCXX 3.4.25；Node 22 的 Linux ARM64 平台条件包括 glibc 2.28 与 Linux 4.18。参见 [VS Code 系统要求](https://code.visualstudio.com/docs/supporting/requirements) 和 [Node 22 平台说明](https://github.com/nodejs/node/blob/v22.23.2/BUILDING.md)。

工具链已打包，操作系统、系统图形库和浏览器不随包交付。目标机已有 Edge/Chrome/Chromium 可用于网页；VS Code 浏览器调试要求对应浏览器安装可被识别。麒麟的具体版本、glibc 和桌面环境需在目标机核对；无桌面时仍可使用命令行检查/构建。不要在麒麟上将系统 libc 替换为包中其他版本来尝试适配。

开发包建议解压到普通工作目录，例如 Windows `D:\Work\LiteCodeToolDev`、Linux `~/work/LiteCodeToolDev`。如果解压路径本身包含 liteCodeTool_tmp，使用命令时必须加 `--data-dir` 指向该临时目录之外。

## 2. Windows 开始开发

双击“打开开发环境.cmd”，或指定数据路径：

```powershell
.\打开开发环境.cmd --data-dir 'D:\工作数据\liteCodeTool_datas'
```

会打开包内 VS Code，Node 和 PowerShell 7 仅对本次进程加入 PATH，不修改系统安装。编辑器用户配置保存在包内源码同级 liteCodeTool_tmp，扩展为包内离线扩展。F5 使用既有“前后端联调（演示）”，成功后打开 Edge 调试；生产数据联调选择真实配置并事先传入 INGEST_TOKEN。

命令行入口无需安装系统 Node：

```powershell
.\dev.cmd demo
.\dev.cmd check
.\dev.cmd test
.\dev.cmd build
.\dev.cmd terminal
```

demo 命令持续运行，按 Ctrl+C 停止后再执行其他命令；CMD 若询问是否终止批处理，输入 Y。terminal 打开使用包内环境的 PowerShell 7，当前目录为源码，可执行 npm 命令。

## 3. 麒麟/Linux ARM64 开始开发

用系统 tar 解压交付的 tar.gz，不先在 Windows 中拆开重压。首次启动会在本地校验和展开 Node/npm 与 VS Code，不访问网络：

```sh
tar -xzf LiteCodeTool-Linux-ARM64-Dev-20260909.tar.gz
cd LiteCodeTool-Linux-ARM64-Dev-20260909
bash setup.sh
bash dev.sh check
bash dev.sh build
bash dev.sh demo
```

打开 IDE：`bash ./打开开发环境.sh`。用普通桌面用户运行，不要用 root。打开开发终端：`bash dev.sh terminal`。Linux 使用系统 Bash，不要求 PowerShell。

Linux 可选择 F5“前后端联调（手动打开浏览器）”，待服务就绪后手动打开 http://127.0.0.1:5173。该项同时启动前后端，不要求安装 Edge。使用 Chrome/Chromium 源码断点调试时，按实际安装路径设置现有 Chrome 调试项 runtimeExecutable。浏览器及系统图形库不是 npm 依赖，不能通过 restore 命令补齐。

## 4. 通用命令表

前缀在 Windows 是 `.\dev.cmd`，Linux 是 `bash dev.sh`。各命令均支持 `--data-dir <源码之外的目录>`。

| 命令 | 实际用途 |
| --- | --- |
| demo | 启动当前 Node 后端演示模式及 Vite 热更新服务 |
| live | 启动当前 Node 后端真实模式及 Vite；凭据由 INGEST_TOKEN 提供 |
| frontend | 仅启动 Vite；用 PORT 指向自己的 Java 后端 |
| check | Vue/TypeScript 类型检查 |
| test | 运行现有轻量单测 |
| build | 类型检查、Vite 生产构建、运行目录装配 |
| terminal | 打开已注入包内 Node/npm 的开发终端 |
| restore | 从包内缓存离线执行 npm ci，重新创建当前锁版本 node_modules |

正常开发不需要 restore，已包含完整 node_modules。只有依赖目录损坏或需要核验重装时使用；它会替换当前源码的 node_modules，但不改源码与锁文件。先停止开发服务。新增或升级依赖须在联网准备环境更新 package-lock.json，并重新准备**两个平台**的依赖和缓存，再重新交付；现有缓存不承诺包含任何未来依赖。

开发页面默认 `http://127.0.0.1:5173`，当前 Node 开发后端直接启动默认 8787；通过环境 PORT/VITE_PORT 修改。所有完整环境变量及单位配置见数据手册，不在这里维护第二份清单。

构建产物在 `liteCodeTool_tmp/release/app`，其中 web 是可交给 Java 托管的前端静态文件。运行上次构建结果可在开发终端执行 `npm run start:demo`。多大屏和 iframe 入口及测试见 [接口契约](后端接口契约.md#10-iframe-与-java-托管) 与 [iframe 专项用例](../../tests/iframe-embedding.md)。

## 5. Java 对接从哪里开始

1. 阅读接口总表和 bootstrap/ETag/WebSocket 小节。
2. 对照完整字段表定义 DTO，保留可选字段和 null 的区别。
3. 参考 examples 内的 JSON 验证模板、大屏、实体和来源规则。
4. 启动 Java 后端后，将 PORT 设为其端口，执行 frontend。
5. 逐项完成接口契约末尾的兼容验收，最后验证跨来源 iframe。

仅换后端不需要改 Vue 页面；若修改响应包装、路径、来源语义或单位，则不再是直接兼容替换。当前源码可作为逐条行为的参考实现。

## 6. 在联网准备机重新出包

Windows 通用资源仍由 `tools/prepare-offline.mjs` 从官方本地 Node、VS Code、PowerShell 7 和 VSIX 目录装配。准备两个平台的项目依赖与 ARM 官方工具链：

```powershell
node tools/prepare-dev-dependencies.mjs
node tools/prepare-arm-devkit.mjs
node tools/export-data-reference.mjs
node tools/package-offline.mjs --target win32-x64 --output ../liteCodeTool_tmp/新的Windows开发目录
node tools/package-offline.mjs --target linux-arm64 --output ../liteCodeTool_tmp/新的ARM开发目录
```

prepare-dev-dependencies 支持 `--output`，prepare-arm-devkit 支持 `--output`、`--downloads`、`--common`；package-offline 支持 `--target`、`--resources`、`--dependencies` 和 `--output`，缺省路径见各工具。依赖准备会联网，只装配平台依赖而不执行跨架构安装脚本；打包阶段只读取本地资源，校验工具链摘要、依赖锁与原生二进制架构。输出目录必须新建，不覆盖旧交付。

Windows 交付压缩为 ZIP，ARM 压缩为 tar.gz，并在包外生成 SHA256。ARM 的 Node/VS Code 原始归档保留在 toolchain，setup.sh 在目标平台展开权限与链接；不能用 Windows node_modules 替换 ARM node_modules。更新任何源码或文档后重新打包，核对 manifest 与交付文件 SHA256。

## 7. 验收边界

出包应核对全部源码摘要、锁版本、对应架构二进制和许可证；Windows 上执行包内依赖恢复、类型检查、构建和前后端服务启动。目标 ARM 机需执行同样命令并测试 IDE 与浏览器。

`npm --offline` 成功只能证明缓存能够恢复依赖，不等于完成整机断网验收。真正的离线验收应在目标机断开外网且保留本机回环后，验证热更新、格式化、前后端断点和生产构建。未实测的 ARM、断点或整机断网能力须在随包验收记录中明确标注，不把二进制架构核对当作运行成功。
