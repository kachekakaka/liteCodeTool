# 后端接口契约（供 Java 后端对接）

本契约描述当前 Node 后端及前端实际使用的协议。Java 实现保持以下 HTTP、WebSocket 和配置语义即可替换后端；数据库、线程模型和框架由实现方选择。业务结构、字段与配置分别见 [数据格式与配置手册](数据格式与配置手册.md)、[完整字段表](数据结构字段表.md)。源码入口为 [server/index.mjs](../../server/index.mjs)、[接入校验](../../server/ingestion.mjs)、[共享校验与合并](../../src/engine/core.ts)。

## 1. 地址、传输与通用约定

- 页面、`/api`、`/ws` 使用同一个来源。开发时 Vite 代理 API 和 WebSocket；生产时可由 Java 同时托管前端静态文件，或由反向代理统一入口。当前前端没有独立 API 基址配置。
- HTTP 请求体是 UTF-8 JSON，必须使用 `Content-Type: application/json`，上限为 **2,000,000 字节**。不支持 multipart、表单、文件直传或批量接入数组。
- 成功响应直接返回下述对象或数组，**没有统一的 code/message/data 外壳**。失败返回 `{"error":"中文原因"}`，HTTP 状态码表示失败类型。204 完全没有响应体。
- JSON 数值必须有限；通用结构拒绝 `__proto__`、`prototype`、`constructor` 键，嵌套深度不超过 24。资源 ID 是 1～80 位字母、数字、下划线、连字符，排除上述保留词。URL 路径和查询参数按 UTF-8 编码。
- JSON 响应使用 `Cache-Control: no-store`。前端单次 HTTP 请求超时为 10 秒。
- 配置资源的 `revision` 是带双引号的强 ETag。当前 Node 对磁盘 UTF-8 JSON 原文计算 SHA256 并加双引号；Java 可使用自己的强版本机制，但应将版本作为不透明字符串原样传回和比较。
- 管理和读取接口没有登录流程；真实数据入口仍使用既有的 Bearer token。iframe 集成不需要将 token 交给浏览器。

定义：`Revisioned<T> = {"data": T, "revision": "\"版本值\""}`。只有集合、bootstrap、import 响应使用这一包装；单项 GET/POST/PUT 的正文是原始配置，版本位于 HTTP `ETag` 头。

## 2. 接口总表

所有表中的参数、状态和返回值详解见后续对应小节；表外的业务接口当前不存在。

| 方法 | 路径 | 入参 | 成功响应 |
| --- | --- | --- | --- |
| GET | `/api/health` | 无 | 200，服务状态 |
| GET | `/api/bootstrap` | 无 | 200，初始化对象 |
| GET | `/api/schemas` | 无 | 200，`Schema[]` |
| GET | `/api/templates` | 无 | 200，`Revisioned<ComponentTemplate>[]` |
| GET | `/api/templates/{id}` | 模板 ID | 200，`ComponentTemplate` + ETag |
| POST | `/api/templates/{id}` | 完整模板 + `If-None-Match: *` | 201，规范化模板 + ETag |
| PUT | `/api/templates/{id}` | 完整模板 + `If-Match` | 200，规范化模板 + ETag |
| GET | `/api/screens` | 无 | 200，`Revisioned<ScreenConfig>[]` |
| GET | `/api/screens/{id}` | 大屏 ID | 200，`ScreenConfig` + ETag |
| POST | `/api/screens/{id}` | 完整大屏 + `If-None-Match: *` | 201，规范化大屏 + ETag |
| PUT | `/api/screens/{id}` | 完整大屏 + `If-Match` | 200，规范化大屏 + ETag |
| DELETE | `/api/screens/{id}` | 大屏 ID + `If-Match` | 204，无正文 |
| GET | `/api/entities/{type}/{id}` | 模式、记录或目标 ID、可选查询参数 | 200，单条快照 Envelope |
| POST | `/api/ingest` | Bearer token + 单条增量 Envelope | 202，`{"accepted":true}` |
| POST | `/api/import` | 完整大屏导入包 | 201，新大屏和新模板的版本包装 |
| POST | `/api/demo` | `{"action":"toggle"}` 或 `{"action":"discover"}` | 200，`{"paused":boolean}` |
| WebSocket | `/ws` | 握手，无订阅正文 | hello、update、heartbeat、demo-state |

没有模板删除、实体删除、模式写入、历史查询、独立导出、服务端复制/重命名、分页、搜索和 WebSocket 数据上报接口。前端复制/重命名复用配置接口，导出在浏览器内组装 JSON。

## 3. 服务状态与初始化

### GET /api/health

```json
{"app":"LiteCodeTool","version":"0.2.0","sessionId":"每次进程启动生成的 UUID","mode":"live","lastUpdate":null,"paused":false}
```

`app/version/sessionId/mode` 是字符串；`mode` 只能是 `demo` 或 `live`。`lastUpdate` 是本进程最后一次接收更新的服务器毫秒时间，尚无更新为 null，重启后不从快照恢复。`paused` 为演示暂停状态，真实模式为 false。sessionId 用于区分运行会话，不能作为数据序号或资源版本。

### GET /api/bootstrap

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| mode | `"demo" \| "live"` | 数据模式 |
| schemas | `Schema[]` | 当前运行目录的模式定义 |
| templates | `Revisioned<ComponentTemplate>[]` | 全部已保存模板 |
| screen | `Revisioned<ScreenConfig> \| null` | 优先 screen_main，否则按 ID 排序取首个；没有大屏为 null |
| screens | `{id:string,name:string}[]` | 大屏目录摘要，不包含完整组件 |
| snapshots | `Envelope[]` | 最新底账，含逐字段 fieldTimestamps，不含历史 |
| lastUpdate | `number \| null` | 与 health 相同 |
| paused | boolean | 与 health 相同 |

空大屏目录必须返回 `screens: []`、`screen: null`，不得在读接口或每次启动时重新创建已删除的大屏。前端先用此接口初始化，再按路由 ID 读取指定大屏。单项路由找不到时应返回 404，不能悄悄替换为默认大屏。

### GET /api/schemas

直接返回当前 `Schema[]`。完整内置示例：[schemas.json](examples/schemas.json)。这是读取接口；新增字段的配置步骤见数据手册。

## 4. 模板和大屏资源

### 集合与单项读取

`GET /api/screens` 或 `/api/templates` 无请求体、无分页参数。空集合返回 `[]`。Node 按合法 JSON 文件名排序读取。

集合示意：

```json
[{"data":{"id":"screen_demo","name":"测试大屏","bindingVersion":2,"resolution":{"width":1920,"height":1080},"background":"#030B17","components":[]},"revision":"\"abc123\""}]
```

单项 GET 正文仅包含上述 `data` 对象，并在响应头返回 `ETag: "abc123"`。真实 Node 的版本内容为 64 位 SHA256，此处是缩短的说明示例。

### 新建：POST /api/{screens|templates}/{id}

- 由调用方产生合法且不重复的 ID，路径 ID 必须等于正文 `id`。
- 发送完整结构（不是补丁）；必须携带 `If-None-Match: *`。
- 不存在时返回 201、规范化后的完整配置以及新 ETag。已存在返回 412；缺少规定前提返回 428。
- 大屏的模板引用必须已经存在。槽位可以指派尚未有业务数据的目标，保存不会因此拒绝。

示例请求：

```http
POST /api/screens/screen_demo HTTP/1.1
Content-Type: application/json
If-None-Match: *

{"id":"screen_demo","name":"测试大屏","bindingVersion":2,"resolution":{"width":1920,"height":1080},"background":"#030B17","components":[]}
```

### 更新：PUT /api/{screens|templates}/{id}

- 先 GET，再将读取的 ETag **连同双引号**放入 `If-Match`；正文为修改后的完整资源。
- 成功返回 200、规范化完整资源及新 ETag。调用方必须更新自己的版本，不能继续使用旧版本。
- 无 If-Match 返回 428；版本过期或使用 `If-Match: *` 返回 412。并发检查和写入必须处在同一个原子操作或事务中。
- 规范化移除 `workshopPreviewTarget`，大屏转换为 `bindingVersion: 2`；旧来源绑定兼容规则见数据手册。调用方应采用响应中的配置作为新基线。
- 修改共享模板前，需使用候选模板校验**所有引用它的大屏的有效控件配置**；更新会使某大屏失效时返回 409，保留旧模板。更新合法时其引用者下次读取使用新模板。
- 配置保存不发送 WebSocket 配置变更消息；已打开的其他窗口不会被自动重载。

### 删除：DELETE /api/screens/{id}

必须携带读取时的 If-Match；成功 204，不含 JSON。没有资源返回 404，缺版本 428，版本不匹配（包括星号）412。删除与该资源保存共用并发控制。只删除大屏，不删除共享模板和实体数据。允许删除最后一个大屏。

重命名：GET 完整大屏，修改 name，然后 PUT。复制：GET，生成新的大屏 ID 和每个 instanceId，修改名称，再 POST；引用共享模板，不复制实体数据。批量操作不存在。

## 5. 单条实体底账

`GET /api/entities/{type}/{id}`：不带查询参数时 id 是实际记录 ID。例如 `/api/entities/projectile/P-101-radar2`。

`GET /api/entities/projectile/P-101?byTarget=1&source=%E9%9B%B7%E8%BE%BE2`：此时 id 是业务批号。只有 `byTarget=1` 启用按目标查找；source 只在此模式生效，省略或空串自动选择一条记录，指定来源必须精确匹配。自动选择与无回退规则见数据手册。

```json
{"type":"projectile","id":"P-101-radar2","timestamp":1788940001000,"data":{"batch_no":"P-101","source":"雷达2","altitude":1.2,"speed":36},"fieldTimestamps":{"batch_no":1788940000000,"source":1788940000000,"altitude":1788940001000,"speed":1788940000000}}
```

响应 id 是**实际记录 ID**，timestamp 为字段时间最大值；不同字段不一定同时更新。无匹配返回 404 `该实体尚无初始底账`。全局模式底账通过 bootstrap 获取，不能使用此接口按 `_global` 获取。

## 6. 外部实时数据接入

`POST /api/ingest`，仅真实模式启用。请求头 `Authorization: Bearer <INGEST_TOKEN>`，既有 Node 配置要求 token 至少 24 字节；启动器生成的 token 在真实数据目录 connection.json 中。

```http
POST /api/ingest HTTP/1.1
Content-Type: application/json
Authorization: Bearer <服务端实际配置值>

{"type":"projectile","id":"P-101-radar2","timestamp":1788940000000,"data":{"batch_no":"P-101","source":"雷达2","altitude":1,"speed":36}}
```

示例时间须替换为当前源毫秒时间。返回 202 `{"accepted":true}`，表示校验和内存合并已处理并触发广播；**不保证这一刻已落盘，也不表示旧时间戳字段一定更新了状态**。Node 定时持久化间隔为 5 秒。

每个请求只接收一条 Envelope，发送数组返回 400。数据校验和单位换算详见数据手册。顶层客户端 fieldTimestamps 被剥离；服务端为每个已接收字段保存源时间。模式不存在、字段不存在、字符串数字、身份变化、重复目标来源和超前时间等返回 400；演示模式或凭据无效为 403。

Java 后端对接真实生产源时也可在内部适配器直接生成规范 Envelope，无需绕 HTTP 调自己，但推送与快照必须遵守相同格式、单位和时间合并规则。

## 7. 导入与导出

`POST /api/import`，无 If-Match，正文结构：

```typescript
{ format: 'litecode.screen.v1'; screen: ScreenConfig; templates: ComponentTemplate[] }
```

templates 最多 150 项；必须包含 screen 引用的所有模板，不能有重复旧模板 ID。完整文件示例：[builtin-screen.litecode.json](examples/builtin-screen.litecode.json)。发送 JSON 文件内容即可，不能发送文件名或 multipart。

服务端为全部导入模板分配 `tpl_` + 无连字符 UUID，为大屏分配 `screen_` + 无连字符 UUID，映射 templateId；名称截取原名至 110 字符后追加 ` · 导入`。instanceId 保留原值，按新大屏范围校验。全量规范化、校验后再持久化，失败须清理本次新建资源，不能遗留半个导入包。

201 响应：

```typescript
{ screen: Revisioned<ScreenConfig>; templates: Revisioned<ComponentTemplate>[] }
```

不覆盖原大屏和原模板。格式错误、缺引用、重复 ID 或无效配置为 400。当前有些异常结构在规范化前触发异常会走通用 500；调用方应按规范结构发送，不依赖这类异常路径。

导出没有 HTTP 接口。前端将当前大屏及其引用模板组装为上述包下载，包内不含模式、业务快照、历史、凭据和版本。跨系统导入前应保证目标系统具有相同的业务模式字段。

## 8. 演示控制

`POST /api/demo`，正文只有 action 字符串：

- `toggle`：切换暂停/继续自动演示推流。
- `discover`：上报固定 ID `413000999` 的演示船舶和全港统计变化；它不是通用“创建实体”接口，也不保证每次产生新 ID。

两者成功返回 200 `{"paused":false}`（或 true），并广播 demo-state；discover 还广播数据 update。未知动作 400，真实模式调用为 404。

## 9. WebSocket 协议

地址严格为 `ws://服务地址/ws`，HTTPS 使用 `wss://服务地址/ws`；不要追加查询字符串。握手没有业务 token、子协议、topic、订阅或 screenId。每个窗口一条连接，服务端对所有连接广播全部模式的更新，前端自行按配置取值。

所有应用消息是 UTF-8 文本帧中的 JSON 对象，由 kind 区分：

| kind | 方向 | 字段 | 时机 |
| --- | --- | --- | --- |
| hello | 服务端 → 客户端 | sessionId:string，mode:demo/live，paused:boolean | 连接成功立即发送 |
| update | 服务端 → 客户端 | envelope:Envelope，不含客户端伪造的字段时间 | 接收有效外部数据或生成演示数据 |
| heartbeat | 服务端 → 客户端 | timestamp:number，服务器当前毫秒时间 | 每 15 秒 |
| demo-state | 服务端 → 客户端 | paused:boolean | 演示动作执行后 |

```json
{"kind":"hello","sessionId":"a-session-uuid","mode":"live","paused":false}
```

```json
{"kind":"update","envelope":{"type":"projectile","id":"P-101-radar2","timestamp":1788940001000,"data":{"altitude":1.2}}}
```

```json
{"kind":"heartbeat","timestamp":1788940015000}
```

```json
{"kind":"demo-state","paused":true}
```

服务端同时每 15 秒发送 WebSocket 协议层 ping，未收到上一轮 pong 则断开；浏览器自动回复协议 pong，不发送 `{"kind":"pong"}`。入站最大消息 1024 字节，无业务消息处理器；不能经此连接 ingest。出站排队超过 2,000,000 字节时断开慢连接。

前端断开后按 1、2、4…秒重连，基础延迟封顶 30 秒，另加 0～300ms 抖动；重连成功重新读取 bootstrap 快照，补最新值而不伪造断线期间历史。没有消息序号、ACK、历史重放、断点续传或历史 REST API。时间戳是字段新旧判定依据。模式切换清空上一模式实体和历史。

## 10. iframe 与 Java 托管

- 管理 `/screens`，编辑 `/screens/{id}/edit`，展示 `/screens/{id}/view`，嵌入 `/screens/{id}/embed`；工坊 `/workshop/{templateId}`，数据状态 `/data`。实际路由见 [router](../../src/router/index.ts)。
- iframe 使用独立大屏 URL：`<iframe src="http://服务器:端口/screens/实际ID/embed" style="width:100%;height:100%;border:0"></iframe>`。父容器必须有明确高度。
- 目标和来源可在嵌入页内临时切换，仅保存在该页面内存；无保存按钮，也没有 postMessage 宿主控制协议或通过查询参数预设目标的协议。
- 展示和 embed 的 HTML 响应不能设置禁止 iframe 的 X-Frame-Options 或 frame-ancestors；反向代理也要保持此行为。父站 CSP 的 frame-src 须允许应用地址。
- 深层页面 GET/HEAD（Accept 包含 text/html）返回前端 index.html；`/api`、`/ws`、缺失 assets 或带扩展名文件不能被 SPA fallback 变成 HTML。生产静态根目录使用构建后的 web。
- 开发接 Java：单独运行 Java，例如监听 8788；设置 PORT=8788 后单独启动包内 Vite（`node node_modules/vite/bin/vite.js`），让现有 `/api` 和 `/ws` 代理转发。不要同时运行 `dev.mjs`，它会再启动 Node 后端。HTTP 和 WS 代理必须指向同一服务。
- [iframe 专项用例](../../tests/iframe-embedding.md) 和 `tools/iframe-smoke.mjs` 可用于 Java 替换后验收。跨来源 iframe 能加载不等于开放 API CORS；当前 API 未声明跨来源 fetch 支持。

## 11. 错误与 Java 验收清单

| 状态 | 常见原因 | 调用方处理 |
| --- | --- | --- |
| 400 | JSON/字段/身份/配置不合法 | 读取 error，修正正文 |
| 403 | ingest 未启用、演示模式或凭据错误 | 核对模式及配置 |
| 404 | 接口/大屏/模板/实体不存在 | 展示缺失状态，不替换为其他资源 |
| 409 | 模板改动会破坏已有大屏 | 调整引用或另存新模板 |
| 412 | 版本冲突、创建重名、非法星号覆盖 | 重新 GET，再由用户决定如何合并 |
| 413 | 超出 2,000,000 字节 | 减小配置或内嵌图片 |
| 415 | Content-Type 错误 | 使用 application/json |
| 428 | 缺少创建/更新/删除版本前提 | 补正确的条件请求头 |
| 500 | 读写、解析或未被业务分支捕获的异常 | 保留原资源，检查后端日志 |

Java 替换的最小验收顺序：bootstrap 空集合与非空集合 → 单项读取 ETag → 新建/改名/复制/更新/删除 → 过期版本并发拒绝 → 模板跨屏引用校验 → 导入重映射及失败回滚 → 所有内置模式接入 → 多来源隔离 → 稀疏/乱序/null/逐字段快照 → WS 重连补账 → 独立大屏深链刷新与跨来源 iframe。

Java JSON DTO 必须区分“字段未出现”与“明确 null”。对于稀疏 data、controlOverrides 和来源映射，可使用 Map/JsonNode 并检查键是否存在；不能将 null 统一当作不更新，也不能用基本类型的 0/false 代替未出现。毫秒时间建议 long，业务 number 使用能保留小数的数值类型，传给前端时仍为 JSON number。
