# 0011. 同拍时序航迹线性对齐与规范闭环整改

针对代码审查（Code Review）中暴露的展示层内联复杂算法、5 秒模糊容差对齐带来的 $O(N^2)$ 计算瓶颈、开发手册类型契约脱节、双轴校验单测虚假绿灯、换船浮层向上翻折偏移符号错误等问题，系统确立同拍时序航迹线性对齐、纯计算函数下沉、类型契约真源对齐与样式及文案规范修复全套架构决策。

## 决策背景与核心权衡

1. **同拍物理时序模型与源端职责解耦（Same-Tick Alignment & Boundary Separation）**：
   - **痛点与性能瓶颈**：原方案在 UI 组件渲染计算中采用 5 秒时间戳容差双重循环查找最近邻匹配，当窗口内有点数 $N$ 时，每次渲染产生 $O(N^2)$ 计算量（如 500 点产生 250,000 次比较），不仅造成不必要的前端 CPU 浪费与潜在掉帧风险，还将源端数据治理负担错置给大屏渲染端；
   - **业务真源与架构分工**：在 AIS 或传感器实际采集推流中，同一物理实体的经度（X 轴）与纬度（Y 轴）在同一帧报文中打包下发，时间戳天然一致。若源端存在异步脱节或采样抖动，应由后端采集与清洗服务保障数据对齐，大屏前端拒绝充当复杂的容差清洗器；
   - **极简 $O(N)$ 线性对齐**：前端通过时间戳哈希或双指针进行单次线性扫描对齐（$O(N)$ 复杂度），耗时由毫秒级降至微秒级，保障大屏 60FPS 丝滑高频推流重绘。

2. **纯函数核心算法下沉与无分支真单测（Pure Engine Function & Strict Testing）**：
   - 严格落实《快速开发手册》“数据解析与时效算法下沉至 `src/engine/core.ts` 纯函数层”的硬性规范，将双轴航迹点对提取与对齐收敛为纯函数 `alignTrajectoryPoints`，组件（`LineChart.vue`）仅负责调用并接收点对进行 SVG 渲染；
   - 在 `tests/core.test.ts` 中彻底修复单测 fixture 缺少折线图控件导致的无条件断言跳过（虚假绿灯），为契约校验与航迹对齐提供真实、可复现的自动化单测保护。

3. **类型契约与开发手册真源对齐（Flat Control Contract vs Documentation）**：
   - 确立代码真源 `src/types.ts` 中扁平单体接口 `export interface Control { type: ControlType; props: ControlProps; ... }` 为项目唯一权威；
   - 修正《快速开发手册.md》中残留的 Tagged Union 演示片段，杜绝新开发者困惑，避免在小规模低代码场景下引入过度类型多态重构。

4. **X 轴对象槽位契约消费与交互收敛（X-Axis Slot Consumer）**：
   - 自由双轴模式下消费 `xAxisSlotId` 契约：缺省默认绑定首条曲线所属的对象槽位；
   - 属性面板检查器在多系列场景下支持显式选择“X 轴对象槽位”，保证多船相对航迹或双船同屏对比时语义绝对明确。

5. **样式与交互细微缺陷收敛（UI Flaw Remediation）**：
   - 修复 `insitu-popover.popover-up` 向上翻折偏移为 `bottom: calc(100% + 8px)`，确保浮层与卡片顶部留有 8px 安全间隙，不再向内遮挡卡片边框；
   - 补全工坊脱敏提示完整说明：“模具预览中 · 实际船舶在投屏大屏中指派”；
   - 消除跨组件直接 DOM 查询（`document.querySelector`），统一使用 Vue 标准声明式引用或微任务聚焦。
