# 0013. 双维度目标重定向、弹目标度量规范与表格列规则真源化

针对测控大屏在多源异构传感器（雷达、遥测、光测）密集探测飞行弹目标时暴露的 Y 轴度量量纲缺失、大屏运行态与工坊编辑态切源不对称、多传感器同屏比对冲突，以及表格列状态颜色硬编码导致属性面板脱节等问题，系统确立双维度目标重定向、弹目标工程度量规范化、12 目标 × 8 数据源仿真推流与表格列颜色 100% 规则真源化的架构决策。

## 决策背景与核心权衡

1. **飞行目标工程度量规范化（Projectile Schema Metric Standards）**：
   - **痛点**：既有飞行目标（`projectile`）Schema 中高度为 `m`（米）、速度为 `m/s`（米/秒），而真实测控指挥现场对弹道与高空目标的通用工程量纲为**高度 `km`（千米）**与**速度 `km/h`（千米/小时）**；
   - **架构决策**：将 `projectile` Schema 中的字段单位正式调整为 `altitude: km` 与 `speed: km/h`；组件工坊内置基础模板保持海事船舶（`vessel`）为初始默认模板，用户在属性面板切换为“飞行目标”时，折线 Y 轴度量字段即刻提供规范的高空高速工程度量选项。

2. **双维度目标重定向与严格槽位来源权威（Dual-Dimension Retargeting & Strict Slot Authority）**：
   - **痛点与脱节**：大屏画布上的就地“切换监控对象”浮层此前仅支持选择实体标识（批号/MMSI），无法切换数据来源；而组件工坊编辑栏仅支持曲线级配置数据源，缺少预览实体选择。两端交互严重不对称，无法满足同一目标由不同传感器交叉测量时的快速对比需求；
   - **双维度重定向模型**：在组件实例扩展 `slotSourceBindings: Record<string, string>` 字段。大屏运行态浮层中，每个槽位（对象 1、对象 2 等）均提供【目标实体（如 P-101）】与【数据来源（如 雷达1、遥测等）】两级联动下拉框；组件工坊编辑栏对称提供【预览目标】下拉选择；
   - **严格槽位来源权威（Strict Slot Source Authority）**：大屏运行态由指挥员指派的槽位数据来源拥有绝对优先权，一旦槽位指定来源，该槽位下的曲线强制按所选来源执行点位过滤与展示，杜绝设计时静态配置与运行时动态意图冲突。

3. **12 目标 × 8 测控数据源的仿真流架构（12 Targets × 8 Sources Simulation）**：
   - **业务场景对齐**：测控现场预计有 12 个左右弹目标，每个目标有 8~10 个传感器来源。
   - **仿真支撑**：在演示环境（`--demo`）的 `demoEnvelopes` 与推流循环中，生成 `P-101` ~ `P-112` 共 12 个弹目标实体，覆盖 `雷达1`、`雷达2`、`雷达3`、`雷达4`、`遥测1`、`遥测2`、`光测1`、`光测2` 共 8 个真实测控站来源，生成连续平滑的时序运动轨迹，使多目标、多站点交叉对比具备真实数据基础。

4. **表格列颜色 100% 规则真源化（Table Column Color Rule Truth）**：
   - **暗箱逻辑剥离**：彻底删除 `TableControl.vue` 中遗留的 `statusClass` 硬编码类名映射逻辑；
   - **规则引擎真源驱动**：在内置表格模板配置中，将航行状态与目标状态颜色以 `tableColumnRules` 显式声明；在 `TableProperties.vue` 检查器中，优先选中已有规则的列进行展示与编辑，实现“界面呈现完全源自属性面板配置，用户所见即可直接编辑”。
